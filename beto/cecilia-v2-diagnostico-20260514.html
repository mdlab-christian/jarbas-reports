Gaps Criticos

2 P0 bloqueantes · 3 P1 importantes · 2 P2 aceitaveis
P0 Cecilia NAO cria atividades automaticamente
Campo requer_atividade: sempre FALSE (1.261/1.261). Campo atividade_id: sempre NULL (1.261/1.261). Quando a Cecilia classifica algo como juridica_estrategica (urgencia A), nada acontece no MdFlow.
Impacto: Uma sentenca desfavoravel com urgencia A e detectada — classificada — e fica parada em intimacoes. Ninguem recebe alerta. Nenhuma atividade e criada. O advogado precisaria entrar em /controller e procurar manualmente.
P0 Monitoramento continuo inexistente
A Cecilia so processa quando alguem faz upload manual de um XLS do EPROC. Nao ha cron que verifique processos novos diariamente. A Judit fazia polling automatico. A Cecilia atual precisa de upload manual toda semana.
Impacto: Se o upload atrasar 1 semana, prazos processuais podem passar despercebidos. E o principal motivo pelo qual a Cecilia ainda nao pode substituir a Judit operacionalmente.
P1 Campos basicos sempre NULL na tabela intimacoes
Todos os 1.261 registros tem NULL em: titulo, data_intimacao, advogado_id, classe_cecilia, confianca_ia (flat) e resumo_ia. Os dados existem no CMB mas nao sao propagados para intimacoes.
Impacto: Frontend quebrado — listagem sem titulo, sem data, sem responsavel. Impossivel construir UI funcional sem esse fix.
P1 Sem alerta Telegram para urgencia A (imediata)
69 intimacoes classificadas como urgencia A (imediata) nao dispararam nenhuma notificacao. O advogado responsavel nao recebeu aviso por Telegram ou qualquer canal.
Impacto: Risco operacional — prazos urgentes passam sem acao se o advogado nao consultar ativamente o /controller.
P1 90 CMBs do T18 com documento nao capturado
90 movimentacoes brutas tem evento_url mas documento_raw=NULL (capturadas antes do fix P0-02). O Worker C analisou essas intimacoes com texto limitado — qualidade inferior.
P2 processo_id null em 58 intimacoes (4,6%)
Processos do XLS que nao existem na tabela processos do MdFlow. Nunca foram cadastrados manualmente. Sem vinculo com o processo principal, atividades nao podem ser atribuidas.
P2 Playbooks nao especializados para negocacao indevida
PB1-PB7 foram escritos para o contexto do Controller (Joao). Falta playbook especifico para padroes Boa Vista, Serasa, SPC, Atacadao — os reus mais comuns do MP Advocacia.

Arquitetura — Pontos de Quebra

Fragilidades Worker A (Playwright)
  • !Seletores CSS hardcoded — TJRS atualiza HTML → Worker para de extrair
  • !TOTP 2FA timing — janela de 30s pode expirar em pico de carga
  • !Mac Mini como SPOF — sem redundancia, sem failover
  • !Sessao EPROC expira a cada 3,5h — overhead periodico
  • !Sem deduplicacao — re-upload de XLS gera duplicatas
  • !Worker A idle apos processar XLS — sem watchdog
Fragilidades Worker C (Sonnet 4.6)
  • !search_similar_cases depende de pg_trgm — falha silenciosa
  • !lookup_judge raramente tem dados — tabela juizes provavelmente vazia
  • !HTTP fallback anonimo raramente funciona — EPROC exige sessao
  • ✗Sem log estruturado do tool_use — dificil depurar
  • !Polo detection fragil — fallback por classe CSS
  • ✗Sem captura de PDFs (apenas HTML do EPROC)
