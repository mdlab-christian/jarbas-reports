A grande sacada: UM agente, TRÊS interfaces

"Imagine que você tem uma assistente. Ela atende você por WhatsApp, atende sua equipe pelo navegador da empresa, e você fala com ela no terminal do seu Mac quando está programando. É a mesma pessoa, o mesmo cérebro, a mesma memória. Só muda o canal."

Cada super agente nosso tem 3 entradas:

  • MdFlow — o app web da empresa (advogados usam diariamente)
  • MdOs — Claude Code rodando direto no terminal do Mac (eu, CTO)
  • Telegram — via OpenClaw (e logo Hermes)

Mudei uma regra de negócio do agente OlivIA? Funciona simultaneamente nas 3 interfaces. Adicionei um playbook jurídico novo? Todas as 3 interfaces leem o mesmo arquivo. O usuário escolhe a interface conforme o contexto.

O cérebro do projeto: Obsidian + RAG

"Esses agentes não são tudo IA. A IA é só o motor. O cérebro está em arquivos Markdown que vivem num Obsidian."

a) O que é Obsidian (pro leigo)

App de notas que salva tudo em arquivos .md no seu computador. Texto puro. Você pode abrir no Bloco de Notas se quiser. Sem banco de dados, sem nuvem proprietária.

b) Como usamos como cérebro

  • Cada super agente tem um vault próprio (uma pasta de notas)
  • olivia-vault tem: identidade (SOUL.md), estilo (STYLE.md), exemplos validados (EXAMPLES.md), 37 playbooks jurídicos, memória de erros já corrigidos (ERRORS.md), memória de aprendizados (MEMORY.md)
  • Quando o agente vai responder algo, ele LÊ esses arquivos primeiro pra saber quem ele é, como ele fala, o que aprendeu antes
  • Toda vez que treinamos o agente, ele atualiza a memória sozinho

c) Onde entra o RAG

  • RAG = Retrieval Augmented Generation. Em português: "primeiro busca, depois gera"
  • OlivIA tem 1.353 jurisprudências (decisões judiciais) e 1.258 trechos de petições antigas indexados via embeddings
  • Quando vai gerar uma peça jurídica, primeiro busca o que é relevante (pgvector no Supabase) e depois usa isso como contexto pra IA
  • O Obsidian sincroniza entre os 3 Macs em tempo real (Obsidian Sync). Edito uma regra no celular → propaga pro servidor em segundos
  • Sem deploy. Sem reinício. Hot reload de cérebro.

Esta é a parte que faz devs avançados pirarem: a inteligência mora em arquivos de texto que qualquer um edita.

Arquitetura física: UM Mac Mini, MUITOS usuários

"Tem um Mac Mini M4 aqui no escritório. Um computador só. Mas dentro dele, cada super agente roda como se fosse um usuário macOS separado. Como se cada um tivesse seu próprio computador."

Analogia pro leigo: apartamento com vários quartos

  • Cada quarto tem dono próprio (user macOS)
  • Cada um tem suas chaves (permissões), seu armário (filesystem), seu telefone (porta de rede)
  • Se um quarto pega fogo (bug), os outros não pegam
  • A administradora do prédio (admin) consegue entrar em qualquer quarto se precisar

Pro técnico:

  • Cada user macOS tem UID próprio (502, 503, 504, 506, 508, 509)
  • Cada um tem um LaunchAgent (auto-restart se cair)
  • Porta HTTP exposta no Tailscale (VPN privada entre nossos Macs)
  • SSH cross-user permite admin entrar em qualquer um pra debugar
  • Logs separados, processos isolados, segurança real

Como os 5 agentes conversam entre si

Quando você tem 5 agentes em produção, eles precisam conversar. A gente fez um protocolo multi-agent simples:

  • Cada agente tem porta HTTP exposta no Tailscale (VPN privada entre os 3 Macs)
  • Envelope JSON canônico de request:
{ "request_id": "uuid", "contexto": "pagina.acao", "organizacao_id": "uuid", "actor_user_id": "uuid", "origem_rota": "/pagina", "data": { ... } }

Response canônico (HTTP 200 sempre, mesmo em erro):

{ "success": true, "message": "...", "action": "toast_refresh", "data": { ... }, "error_code": null }

Exemplos do dia-a-dia:

  • Cecília detecta intimação urgente classe A → manda HTTP pra MIA → MIA escala via Telegram pro advogado responsável
  • OlivIA recebe pedido de petição no MdFlow → consulta Cecília se há intimação relevante no processo → busca jurisprudência via RAG → gera peça
  • Jarbas pode invocar qualquer um via SSH ou API local

Resultado: os agentes trabalham juntos como uma equipe.

Por que isso substitui o n8n

"Antes a gente fazia automações em n8n (igual Zapier, mas open source). Mas n8n tem um limite: ele é uma sequência fixa de passos. Se você quer flexibilidade real, precisa de agente."

🔴 n8n (antes)

  • Workflow fixo: gatilho → passo 1 → 2 → 3 → saída
  • Cada decisão é um IF/ELSE manual
  • Mudar o fluxo = editar visual + redeployar
  • Não tem memória
  • Não aprende
  • Custo cresce com complexidade

🟢 Agentes (depois)

  • O agente decide o caminho cada vez
  • Decisão é raciocínio LLM com contexto
  • Mudar comportamento = editar Markdown no vault (hot reload)
  • Tem memória persistente
  • Aprende com erros (auto-atualiza ERRORS, MEMORY)
  • Custo previsível por chamada

Onde substituímos n8n:

  • Análise de intimações — antes: workflow n8n com regex + IF gigante. Hoje: Cecília classificando com IA + playbook
  • Geração de petição — antes: impossível em n8n. Hoje: OlivIA pipeline-v4
  • Recepção de leads WhatsApp — antes: n8n + Anthropic node. Hoje: Julia com 5 skills + memória cross-conversa
  • Briefing matinal — antes: n8n + queries SQL fixas. Hoje: MIA que entende contexto

Onde n8n continua sendo bom:

  • Workflows simples (webhook → 1 ação)
  • Integrações 1:1 (Stripe → planilha)
  • Tarefas determinísticas sem decisão IA

Hoje temos ~80 workflows n8n ainda rodando — mas a parte "inteligente" da operação migrou pros agentes.

Agora entra o Hermes — o que muda

"Hermes Agent é um framework lançado pela Nous Research em fevereiro de 2026. Ele é o sucessor natural do OpenClaw que eu já uso. Bombou em 10 semanas — 110-140 mil estrelas no GitHub, o framework de agentes que mais cresceu este ano."

5 coisas que Hermes traz a mais que OpenClaw:

1.Skills self-improving

A cada ~15 ações, o agente para, pensa, escreve uma nova skill no vault dele documentando o que aprendeu. Sem ser pedido. ViktorKav (YouTuber BR) mostrou um vídeo dele em que o agente criou sozinho um manual de 6.000 caracteres com os 4 processos do canal, em 4 horas de uso.

2.Divisão de modelos (Pantheon)

Em OpenClaw, tudo cai no modelo principal. Em Hermes, você divide: visão → modelo barato, busca → modelo barato, raciocínio → modelo top. Economia projetada: 40-60% do custo IA.

3.18 plataformas no mesmo gateway

Hoje cada agente é um bot Telegram separado. Com Hermes pode ser Telegram + Discord + Slack + WhatsApp + Signal + Email no mesmo processo. Plug.

4.MCP first-class

Hermes nasceu conectando MCP (Model Context Protocol). Supabase, GitHub, Gmail, Calendar, Notion — tudo plug. Sem reescrever cliente HTTP.

5.Cron em linguagem natural

"Hermes, todo dia às 7h30 me manda um briefing do dia" → ele cria o cron sozinho. Sem editar crontab.

A grande dica pro grupo: migração plug-and-play

"Aqui está a sacada que vai interessar muito o grupo: se você já tem OpenClaw rodando, migra pra Hermes em um comando."
hermes claw migrate

O que acontece:

  • Hermes lê todo seu workspace OpenClaw (~/.openclaw/)
  • Importa: persona do agente, memórias acumuladas, skills criadas, allowlist de comandos, chaves de API, configs de plataforma
  • Em segundos. Sem editar arquivo. Sem dor.
  • ViktorKav reportou: "4 itens migrados, 7 arquivados, 32 pulados, 0 conflitos, 0 erros, segundos"
  • O agente dele (Cláudio) chegou inteiro do outro lado

Quem nunca teve OpenClaw:

curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash

Instala em ~10 minutos. Cria um bot no Telegram pelo @BotFather. Conecta. Roda.

Guia 80/20 — quem do grupo quiser começar

"80% do resultado com 20% do esforço. Se você só vai ler uma seção, leia esta."

Pré-requisitos

  • Um Mac, Linux ou VPS (Hostinger tem template direto, sem terminal)
  • Conta de Telegram
  • Chave de API de algum LLM (Anthropic, OpenAI ou OpenRouter)
Passo 1 —Instalar (5 min)
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
Passo 2 —Criar bot Telegram (3 min)
  • Abre Telegram, procura @BotFather
  • Digita /newbot
  • Dá um nome e username (terminando em "bot")
  • Copia o token
Passo 3 —Setup wizard (5 min)
hermes setup
  • Cola o token Telegram
  • Cola tua chave de API LLM
  • Define teu Telegram User ID (busca em @userinfobot)
  • Confirma. Pronto.
Passo 4 —Configuração CRÍTICA (não pule!)

Vai em "Auxiliary models" e separa:

  • Visão → modelo barato (GPT-5-mini ou Haiku)
  • Busca em sessões → modelo barato
  • Compressão → modelo barato
  • Principal → modelo top (Sonnet 4.6 ou Opus 4.7)

Por quê? ViktorKav levou rate limit no primeiro dia porque deixou tudo no modelo principal. 3 processos falharam por estouro de cota.

Passo 5 —Primeira conversa (1 min)

Abre o Telegram, manda mensagem pro bot. Ele responde. Acabou. Você tem um agente IA rodando no seu computador, 24/7.

Passo 6 —Adiciona MCPs (opcional, recomendado)
hermes mcp add supabase hermes mcp add github # filesystem já vem por padrão
Passo 7 —Deixa ele aprender

Usa uma semana. Pede coisas reais. Ele vai criar skills sozinho documentando os padrões. Vai ficar melhor com o tempo.

Próximo passo (avançado): criar profile separado por agente hermes profile create dev-agent, configurar Pantheon (5 personas com modelos diferentes), conectar Obsidian vault hermes connect obsidian /caminho/vault.

O que melhora na prática: sistema atual + Hermes

Pra mim (CTO):

  1. Vibing operation no celular — falo com Hermes no Telegram, ele opera projetos, abre PRs, faz deploys via SSH nos 3 Macs. Substitui muito uso de terminal.
  2. Briefing matinal mais inteligente — Hermes consolida o que aconteceu ontem nos 3 Macs (via bridge Claude Code OS), sugere prioridades, manda pro Telegram às 7h30.
  3. Skills aprendidas automaticamente — paro de escrever skills manualmente no JARBAS. Hermes observa meu uso, cria/refina sozinho.
  4. Economia 40-60% custo IA — Pantheon (Opus raciocínio + Sonnet padrão + Haiku validação + GPT-nano commodities) cuts costs.

Pra equipe jurídica:

  1. OlivIA mais barata — em shadow, valido se Pantheon mantém qualidade. Se OK, equipe ganha throughput com mesmo custo.
  2. Notificações Cecília via Hermes — backups automáticos, rollback de skills, GitHub privado de configs.
  3. MIA mais responsiva — modelos auxiliares mais rápidos = respostas em segundos.

Pra arquitetura:

  1. Resiliência multiplicada — Hermes vive PARALELO ao OpenClaw. Cai um, outro continua. Não substituição, adição.
  2. Sandbox de fábrica — Hermes roda em Singularity por padrão. Agente erra comando → erro contido. Hoje rodamos sem isolation.
  3. Multi-instância via profiles — hermes profile create permite ter agentes especializados no mesmo Mac sem conflito (olivia-shadow, mdflow-orchestrator, etc).

Pra quem é do grupo:

  1. Aprende com a operação madura — vocês veem o que funcionou (vault Obsidian, 3 interfaces, isolamento por user macOS, migração seletiva), copiam o que faz sentido.
  2. Hermes não é "vai trocar tudo" — é "vai adicionar onde faz sentido". Essa é a regra de ouro: se o agente já funciona sem você, não mexe. Se precisa de você pensando junto, Hermes brilha.
