Secao 2 — Causas Raiz (4 bugs)

Bug 1 — use_cadastrar_restricoes.ts nunca chamava drive-pasta-lead ⛔ ativo
  • Leads afetados: 208 leads importados via auditorias na semana de 11/05/2026 — origem=null, coluna_crm='novos'
  • Problema: O hook chamava drive-pasta-restricao para restricoes mas nunca chamou drive-pasta-lead para criar a pasta raiz do lead
  • Efeito cascata: Sem pasta de lead → drive-pasta-restricao nao tem pasta pai → restricoes tambem ficam sem pasta
  • Impacto direto: 683 restricoes processaveis sem nenhuma pasta Drive
Bug 2 — n8n-proxy 502 silencioso ✅ corrigido hoje
  • Onde: use_cadastrar_restricoes.ts e MdzapLeadCadastroDrawer.tsx usavam supabase.functions.invoke('n8n-proxy', ...)
  • Problema: O n8n-proxy retornava 502 silenciosamente → nenhum webhook chegava ao n8n Railway
  • Correcao aplicada: Ambos os arquivos agora usam callWebhook() direto ao Railway
  • Impacto historico: Parte das 259 restricoes (de leads que tem pasta) sem pasta individual
Bug 3 — Task Runner Disconnect no n8n ⚠️ ativo — parcial
  • No Sync Post-Criacao (drive-pasta-lead): 100% de erro. Roda DEPOIS da resposta ser enviada. O no faz: buscar restricoes → chamar drive-pasta-restricao (sleep 800ms cada) → sincronizar documentos. O task runner do n8n desconecta durante execucao longa.
  • No Save Folder ID (drive-pasta-restricao): ~40% de erro. O no faz PATCH via httpRequest no Supabase para salvar drive_pasta_id. Quando falha: pasta existe no Drive mas ID nao salvo no DB → pasta orfa + restricao ainda com drive_pasta_id = null
  • Causa tecnica: this.helpers.httpRequest em Code nodes com execucao longa (muitos awaits + setTimeout) causa disconnect do task runner n8n
Bug 4 — Get Google Token failures ⏳ intermitente
  • Causa: Execucoes simultaneas para o mesmo lead sobrecarregam OAuth refresh
  • Efeito: Falhas de rede temporarias → drive-pasta-restricao termina sem criar pasta
  • Taxa: Afeta ~20% das execucoes com erro
