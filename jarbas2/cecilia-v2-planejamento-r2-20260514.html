Novas decisões emergentes (D22-D31)

D22 — Simplificar para 2 workers (era 3)

Worker A (Playwright/navegação) + Worker B (análise + triagem em 1 prompt). Remove Worker B regex original. Triagem fica embedded no prompt cache de Sonnet 4.6 — custo marginal $0. Tabela cecilia_triagem_regras removida do escopo.

D23 — Marco zero via Cecília Playwright (não Judit)

Worker A ganha modo marco_zero=true. Baixa processo inteiro via botão "árvore" do EPROC. 8.485 processos × ~50-100 docs = ~500K-850K downloads. Pool 3 paralelos. ~8 dias. Resumable via cecilia_marco_zero_checkpoint. Custo ZERO.

D24 — Aba "Cecília" no /controller é UI completa (6 sub-tabs)

Hub completo: Monitor / Playbooks / Treinamentos / Parâmetros / Uploads / Logs. Playbooks migram do filesystem para tabela cecilia_playbooks com versionamento (cecilia_playbooks_versoes). João edita pela UI; cron sincroniza arquivo Obsidian para celular (mantém workflow João).

D25 — Atividades lançadas pelo João são training data

Quando João lança atividade no /controller a partir de uma análise da Cecília, registrar em cecilia_atividades_lancadas (intimacao_id, atividade_id, classe_cecilia, classe_joao, divergencia BOOLEAN). Vira training data para refinamento de playbooks. Substitui ideia original 7.

D26 — Sem piloto + 3 safeguards mandatórios

(1) Kill switch global cecilia_v2_enabled BOOLEAN DEFAULT TRUE em cecilia_settings_global. (2) Métricas anti-regressão em tempo real: movimento_em_duvida, erro_worker_a, tempo_medio_analise, custo_ia_24h. (3) Workers v1 dormentes 30 dias (não deletar). Direto pra produção 8.485 procs.

D27 — Unificar Aba Análise + Aba Cecília no drawer

Drawer da intimação tem aba "Cecília" única (chat conversacional sobre o processo específico). Remove duplicação "Análise" vs "Cecília". Thread persistente em controller_chat_threads com thread_id = numero_cnj.

D28 — Worker B classifica urgência automaticamente

Urgência é output do prompt de análise. Classes: A (crítico, prazo < 5d), B (relevante), C (rotina), D (ruído descartado). Sem necessidade de regras separadas. Worker B decide com base em playbook ativo.

D29 — Sem notificação Telegram urgência A

Q4 respondida — João monitora pela UI. Heartbeat público (ideia 4 aprovada) cobre status geral. Telegram fica para alertas técnicos (worker down, custo IA explodiu, kill switch acionado).

D30 — "Decorrido prazo" sempre escala para análise

Q6 respondida — quando Worker B encontra evento ambíguo do tipo "decorrido prazo sem manifestação", nunca descarta como ruído. Sempre roda análise completa (custo extra é tolerável vs risco de perder intimação importante).

D31 — Backup git de playbooks em repo privado

Cron diário sincroniza cecilia_playbooks (Supabase) → arquivo MD no Obsidian → commit em repo git privado (github.com/mdlab-christian/cecilia-playbooks). Mantém histórico além do versionamento Supabase. Repo privado por confidencialidade (estratégias jurídicas).

Q10 — Marco zero: baixar PDFs físicos ou só texto?

  • (a) PDF + texto (mais robusto, mais espaço)
  • (b) Só texto raw (sem PDF, perde anexos/imagens)
  • (c) Híbrido: PDF só para SENT/DECMER/ACOR (atos decisórios); texto raw para o resto
💡 Recomendo: (c) — economiza ~70% storage e mantém atos decisórios em alta fidelidade.

Q11 — Edição de playbooks pelo João

  • (a) Aprovação CTO antes do Worker B usar
  • (b) Edição direta com versionamento (reverter em 1 clique)
💡 Recomendo: (b) — João é o especialista de domínio; versionamento + rollback dá segurança sem fricção.
