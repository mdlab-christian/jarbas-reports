ROOT CAUSE IDENTIFICADO

drive-pasta-restricao — webhook chamado mas nao existe

O workflow MDFLOW-DRIVE-PASTA-LEAD-v1 chama o webhook /webhook/mdflow/drive-pasta-restricao para criar subpastas de restricao no Drive. Este webhook nao existe em nenhum dos 100+ workflows n8n. Por isso, restricoes.drive_pasta_id e drive_pasta_url sao SEMPRE NULL — e PI/comprovante vao para pastas erradas ou nao chegam ao Drive.

Escala do problema: 266 de 2021 leads tem pasta Drive (13%) — e nenhum tem subpastas de restricao criadas corretamente.

Multi-Estado — Principios de Design

Secao 7
Regras de Arquitetura para o Davi ser Multi-Estado
  1. Deteccao de estado: via advogados.oab_uf — nunca hardcodar "RS" no codigo do Davi
  2. Separadores EPROC por OAB: mapeamento em tabela ou constante por OAB (RS116571 → hifen, RS131163 → ponto, SC/SP → a definir quando testado)
  3. Limite de processos por lote: 30 por OAB (configuravel, nao hardcoded)
  4. Validacoes especificas de estado: nenhuma — todas as validacoes sao agnosticas (7 docs, PI, comprovante etc. sao universais)
  5. EPROC vs outros sistemas: o Davi so chega ate a porta do EPROC (monta o lote); a Mia executa. Se futuramente houver distribuicao em outros sistemas, o Davi nao precisa mudar
Limitacao MVP
EPROC_ESTADOS_SUPORTADOS = ['RS'] // configuracao, nao hardcode // Quando SC/SP forem testados: adicionar nessa config // O Davi nao quebra — apenas nao filtra processos de outros estados
