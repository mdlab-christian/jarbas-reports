S03

[Organizacao Root] ← organizacoes.google_drive_root_id └── [Nome do Cliente/Lead] ← leads.google_drive_folder_id ├── Documentos Pessoais/ ├── Restricoes/ │ └── [Nome da Empresa Re] ← restricoes.drive_pasta_id │ └── [arquivos Tier 2] └── Lixeira/
Tabela Campo Drive Descricao

clientes google_drive_folder_id Pasta do cliente
restricoes drive_pasta_id Subpasta da restricao

processos_documentos google_drive_id ID do arquivo no Drive (pos-sync)
processos_documentos drive_folder_id LEGADO D-36 — 0 registros
🔴
ACHADO CRITICO — processo.google_drive_folder_id
Em rpc_crm_aprovar_triagem: INSERT INTO processos (..., google_drive_folder_id, ...) VALUES (..., r.drive_pasta_id, ...)
O processo nasce com google_drive_folder_id = restricoes.drive_pasta_id → PI vai para pasta correta automaticamente.
Edge case: se restricoes.drive_pasta_id = NULL quando o processo foi criado → trigger fn_propagar_drive_folder_processo copia clientes.google_drive_folder_id → PI vai para pasta errada (raiz do cliente, nao da restricao).

> 0

Secao 9 — Observacoes e Gaps para o Davi

S09
ACH-01

Drive folder edge case — pasta errada para PI

Se restricoes.drive_pasta_id = NULL quando o processo foi criado, processos.google_drive_folder_id pode apontar para pasta do cliente (raiz). Davi Modo 1 deve checar e corrigir este campo antes de gerar PI. Verificar: processos.google_drive_folder_id == restricoes.drive_pasta_id; se divergente, atualizar antes do dispatch.

OBS-02

Bucket correto por tipo de documento

Docs CRM (leads/clientes): leads-docs | Docs processo (upload direto): documentos | Comprovantes/PIs gerados: podem estar em comprovantes ou documentos (bucket varia conforme workflow). Para verificar acessibilidade: usar getSignedUrl e tratar erro 404 — nunca assumir pelo bucket.

OBS-03

Injecao Tier 1 nas pastas de restricao

O Davi deve mesclar Tier 1 + Tier 2 ao contar docs por restricao — igual a logica do useRestricaoDocs. Antes de injetar Tier 1, excluir docs cujo nome bate com /procur|contrat|termo/i. Contagem minima: 5 docs por restricao (conforme mia-preparar-lote).

OK-04

Drive sync e fire-and-forget — usar Storage HEAD check

processos_documentos.google_drive_id = NULL NAO significa que o arquivo nao existe no Storage. O sync Drive e assincrono e pode ter falhado silenciosamente. O Davi deve usar Storage HEAD check (getSignedUrl e verificar se retorna 200), nunca verificar apenas google_drive_id.

LEG-05

Campo processos_documentos.drive_folder_id — LEGADO

Campo marcado como D-36 (legado). Zero registros preenchidos em producao. Ignorar completamente na logica do Davi. Usar apenas processos.google_drive_folder_id e restricoes.drive_pasta_id para referencia de pastas.

OK-06

Minimo de docs — conforme mia-preparar-lote

O lote so e valido se a restricao tiver no minimo 5 documentos (Tier 1 + Tier 2 mesclados, excluindo procuracao/contrato/termo da injecao). O Davi deve aplicar esta mesma contagem antes de decidir se o processo esta pronto para peticionamento.
