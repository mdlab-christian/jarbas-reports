O que é o Davi

SEÇÃO 1

Davi é o agente de validação e preparação de processos jurídicos para distribuição eletrônica via EPROC no MdFlow. Ele opera entre as etapas Preparação e Ag. Distribuição do pipeline CRM → Distribuição, garantindo que nenhum processo chegue ao EPROC com documentos faltando, valor incorreto ou petição inicial ausente.

Posição no pipeline: LEAD APROVADO CRM → [Distribuição / Preparação] → Davi valida → Aprovado → [Ag. Distribuição] → Davi prepara lote → Mia distribui no EPROC
Edge Function 1 davi-validar

Valida 1 processo individualmente. Retorna aprovado bloqueado gerando_pi

7 checagens em sequência

  • 01 Procuração renomeada no Storage
  • 02 Tipos de documentos obrigatórios presentes
  • 03 Quantidade mínima de docs (≥7)
  • 04 Comprovante BV solicitado / existente
  • 05 Valor causa correto (BV: R$15k + dívida)
  • 06 Petição inicial gerada / em geração
  • 07 Arquivos no Storage com path correto
Side effects: renomeia procurações, solicita comprovantes não-BV, dispara geração de PI, salva resultado em davi_validacoes
Edge Function 2 davi-preparar-lote

Orquestra N processos para uma OAB. Filtra elegíveis → valida → cria lote.

Fluxo de orquestração

  • F1 Filtra processos elegíveis (CEF, rate-limit, sem bloqueio)
  • F2 Chama davi-validar por processo (ou usa cache 24h)
  • F3 Se preview=false: chama mia-preparar-lote
  • F4 Cria lotes de distribuição para o worker Mia
Tabela persistida: davi_validacoes — resultado + issues (JSONB) + davi_meta + validado_em por processo

Roadmap de Melhorias

SEÇÃO 4

P0 — Para não alucinar (implementar agora)

01 Action pipeline por issue — botão de ação no modal de verificação P0
Para cada codigo de erro retornado pelo Davi, exibir um botão de ação direto no DaviBadge e no ModalDaviLote tab "Com Erros":
  • valor_divergente + isBV → botão "Corrigir valor causa automaticamente" → UPDATE processos SET valor_causa = 15000 + restricao.valor/100 → invalida cache → revalida
  • comprovante_bv_ausente → botão "Abrir pasta Drive" + texto "Faça o upload e depois clique Revalidar"
  • docs_insuficientes → expansão mostrando quais docs existem vs. quantos faltam
  • tipo_ausente → mostrar qual tipo específico está ausente (não genérico "documento ausente")
02 Botão "Revalidar agora" — invalida cache 24h P0
Disponível em: DaviBadge inline, ModalDaviLote tab "Com Erros", e drawer do processo. Invalida o registro em davi_validacoes e chama davi-validar imediatamente. Essencial após qualquer correção manual — hoje o usuário não tem como confirmar que a correção resolveu o problema sem esperar 24h.
03 Nova EF davi-corrigir-valor-causa P0
Edge Function dedicada ao auto-fix do issue mais frequente (44 ocorrências):
  • Recebe processo_id
  • Verifica isBV e busca restricao.valor do processo
  • UPDATE processos SET valor_causa = 15000 + restricao.valor/100
  • Dispara regeneração de PI via n8n webhook
  • Invalida davi_validacoes (deleta registro ou marca como stale)
  • Retorna novo status após revalidação automática
Versão lote: "Corrigir todos os 44 processos" disponível no Davi Cockpit (melhoria #9).

P1 — Davi mais inteligente

04 Score de prontidão 0-100 com barra de progresso P1
Substituir o binário aprovado/bloqueado por um score ponderado que mostra o quanto falta:
  • comprovante_bv_ausente → -30pts
  • valor_divergente → -25pts
  • tipo_ausente → -20pts por tipo
  • docs_insuficientes → -15pts
  • storage_ausente → -10pts
Exibir como barra colorida no card do processo: verde (80-100), amarelo (50-79), vermelho (0-49).

05 Agrupamento de problemas similares + ações em lote P1
Na tab "Com Erros" do ModalDaviLote, mostrar grupos por issue:
  • "3 processos com valor_causa incorreto → [Corrigir todos em lote]"
  • "5 processos de ADRIANA com comprovante_bv_ausente → [Abrir pasta Drive deles]"
Prioridade operacional: resolver o maior grupo primeiro desbloqueia o lote inteiro.
06 Alertas proativos para processos bloqueados >3 dias P1
pg_cron (ou n8n cron diário) que verifica processos com resultado = 'bloqueado' cujo validado_em > 3 dias atrás. Envia notificação no mural de avisos da homepage do MdFlow com link direto para o processo e o issue pendente. Davi deixa de ser reativo e passa a cobrar resolução.

P2 — Davi como plataforma

07 Revalidação automática pós-upload de documento P2
Trigger no Postgres em processos_documentos INSERT → pg_notify → worker ou webhook → davi-validar chamado automaticamente. Fecha o ciclo de feedback: upload imediatamente reflete no DaviBadge sem intervenção manual.
08 Histórico de validações — timeline por processo P2
Timeline auditável em davi_validacoes: quando foi bloqueado, por quê, quando foi corrigido, por qual usuário (actor_user_id), quanto tempo levou para resolver. Alimenta métricas de eficiência operacional (tempo médio bloqueado por issue).
09 Davi Cockpit — página /distribuicao/davi P2
Página dedicada com visão agregada de todos os processos bloqueados, agrupados por motivo. Ações em lote disponíveis: "Corrigir todos os 44 processos com valor_causa incorreto em 1 clique". Filtros por OAB, advogado, data de bloqueio, score mínimo. Substitui a necessidade de ir ao banco.
10 ML de padrões — sugestões antes de validar P2
Após N validações, Davi aprende quais clientes/empresas têm padrões recorrentes. Exemplos: "todos os processos com réu BOA VISTA têm valor_causa errado → sugerir correção antes de validar", "todos os processos de ADRIANA têm comprovante_bv_ausente → alertar ao criar o processo". Implementação via materialized view com agregações por cliente/empresa/advogado.

Davi como cérebro da operação CRM → Distribuição

Estado atual vs. estado ideal

Hoje o Davi detecta problemas mas não os resolve. Dos 76 processos validados, 45 (59%) estão bloqueados — e a esmagadora maioria (43 processos) por dois issues que têm solução automática conhecida: valor_causa errado (calculável: R$15.000 + dívida BV) e comprovante_bv_ausente (link direto para o Drive do cliente). O operador recebe uma mensagem de erro sem botão de ação, o que cria o pior padrão de UX possível: saber do problema mas não poder resolvê-lo de onde está.

O Davi tem toda a informação necessária para ser um agente resolutivo em vez de apenas diagnóstico. A diferença entre o estado atual e o ideal não é de complexidade técnica — é de action pipeline. Cada código de issue deveria mapear para uma ação determinística, executável com 1 clique, que invalida o cache e revalida automaticamente.

Com os 3 itens P0 implementados (action pipeline + botão Revalidar + EF de auto-fix do valor_causa), o Davi passaria de um detector passivo para um agente que desbloquearia ~43 processos de forma semi-automática, reduzindo o backlog de distribuição sem nenhuma alteração na lógica de validação existente. O caminho CRM → EPROC ficaria finalmente sem fricção.
