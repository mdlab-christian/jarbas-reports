O ponto de entrada de novos processos na distribuição é SEMPRE o CRM. Um lead com restrições processáveis é convertido via ModalDistribuirLead, que chama a RPC distribuir_lead_completo. Processos nunca são criados manualmente direto na distribuição (exceto edge cases admin).

Gaps e Pendências Conhecidas

⚠
Estes não são bugs bloqueantes em produção, mas riscos técnicos identificados que podem causar problemas em edge cases ou dificultar manutenção futura.
Gap 1 — isBoaVista() por string matching
ProblemaLógica usa empresa_nome.includes('BOA VISTA') — frágil para variações de nome como "Boa Vista SCPC", "BOA-VISTA" etc.
RiscoComprovante exibido para processos BOA VISTA com nome levemente diferente, ou bloqueado para empresas com nome similar por acidente
Solução idealFlag sem_comprovante na tabela empresas ou lookup por empresa_id
Gap 2 — sendLocked 1200ms não é lock real
ProblemaDebounce visual de 1200ms após clicar "Enviar" para evitar double-send durante re-render. Não protege contra dois usuários simultâneos
RiscoDois usuários clicando simultaneamente no mesmo processo podem enviar duplicado
Solução idealLock otimista via campo locked_by + locked_at ou transação no banco
Gap 3 — Polling manual no ModalGerarPeticao
ProblemaModal faz polling de 5s por até 120s. Não usa Supabase Realtime
Risco120s de polling mesmo se petição ficar em gerando indefinidamente. Sem cleanup se modal fechar
Solução idealSupabase Realtime na tabela processos_documentos filtrado por processo_id
Gap 4 — Progress bar fake (0→80% em 90s)
ProblemaBarra de progresso é animação cosmética — não reflete progresso real da OlivIA gerando a petição
RiscoUsuário vê 79% por 2 minutos se OlivIA travar. Experiência enganosa
Gap 5 — Colunas denormalizadas sem trigger de sincronia
Problemaempresa_nome, restricao_orgao_nome, restricao_valor etc. em processos precisam de trigger para manter sincronia quando restricoes for atualizada
RiscoDados desatualizados se restrição for editada após criação do processo
Gap 6 — Lote paralelo vs. sequencial
ProblemaPetições geradas em paralelo (Promise.allSettled), comprovantes sequencialmente — sem razão documentada para a diferença
RiscoDificulta debug de falhas em lote. Comportamento inconsistente para o usuário
Gap 7 — UUID vs UF em estados_distribuicao
ProblemaModal carrega estados_distribuicao como UUID para o select, mas rpc_efetuar_distribuicao_manual espera UF (string, ex: "RS"). Conversão feita com .find() no array local
RiscoSe estado não existir no array (cache desatualizado), .find() retorna undefined → RPC recebe undefined silenciosamente
SoluçãoValidar antes de submeter + mostrar erro se estado não resolvido
Gap 8 — 4 fontes para link do Drive
ProblemaPrioridade: drive_processo > google_drive_folder_id > restricao.drive_pasta_url > restricao.drive_pasta_id — confuso e propenso a apontar pasta errada
Solução idealConsolidar em campo único processos.drive_url populado pelo trigger/n8n na criação
