// Query key ['empresas-lista', organizacaoId, filters, page] // Config staleTime: 30_000 pageSize: 20 // server-side

FilaPendentesSection — Fila de Aprovação

Componente colapsável no topo da aba Empresas. Exibe empresas detectadas pela IA em processos que aguardam aprovação humana.

Query da Fila

supabase.from('empresas_aprovacao') .select(` *, empresas!empresas_aprovacao_empresa_id_fkey( nome, nome_fantasia, cnpj, status_aprovacao, criado_por ) `) .eq('organizacao_id', orgId) .eq('status', 'pendente') .order('frequencia_30d', { ascending: false }) .order('created_at', { ascending: true })
ℹ
Ordenação da fila Empresas com maior frequência nos últimos 30 dias aparecem primeiro. Em caso de empate, a mais antiga criada aparece antes — garante que empresas mais relevantes sejam aprovadas prioritariamente.

Badge Count

Exibido em amarelo/warning. Key: ['empresas-pendentes-count']. Atualizado após aprovar, descartar ou mesclar.

Ações por Item da Fila

AçãoPerfisComportamento
Aprovar admin juridico Abre ModalEmpresa mode='approve' com aprovacaoData pré-preenchido (score_blocos, frequencia_30d/90d, cnpj_snapshot, orgao_nome, uf_restricao, categoria_sugerida_id, nome_original_snapshot)
Mesclar com... admin juridico Abre ModalMergeEmpresa — lógica de merge não coberta neste documento
Descartar admin juridico AlertDialog de confirmação → supabase.from('empresas_aprovacao').update({ status:'descartado', processado_em, processado_por_user_id }) → invalida fila

Busca de Similares — RPC rpc_buscar_empresa_similar

Trigger

Disparado no onBlur do campo Nome Fantasia quando o valor tem 3 ou mais caracteres.

Chamada RPC

supabase.rpc('rpc_buscar_empresa_similar', { p_organizacao_id: orgId, p_nome: form.nome_fantasia, p_threshold: 0.5, // trigram similarity mínima }) // Exclui a própria empresa em mode=edit/approve (para não auto-alertar) // Retorna: { id, nome_fantasia, cnpj, similaridade (0-1) }[]

Dependência de Extensão

⚠
pg_trgm obrigatória A RPC usa trigram similarity (pg_trgm). Se a extensão não estiver instalada no Supabase, a busca silencia o erro (fail silently) — nenhum popup de duplicidade é exibido, mas o cadastro não é bloqueado.

PopupDuplicidade

1
RPC retorna results > 0

Popup é exibido abaixo do campo com as empresas similares encontradas

2
Usuário analisa similares

Cada resultado exibe nome_fantasia, cnpj e percentual de similaridade

3
Decisão

Usuário pode ignorar o aviso e continuar criando, ou fechar o modal e usar a empresa existente

Verificação CNPJ Duplicado

Disparado no onBlur do campo CNPJ, separado da busca de similares.

supabase.from('empresas') .select('id, nome_fantasia') .eq('organizacao_id', orgId) .eq('cnpj', form.cnpj) .neq('id', empresa_id) // exclui a própria empresa em mode=edit .limit(1)
⚠
Warning inline (não bloqueia) Se encontrar, exibe warning: "CNPJ já cadastrado na empresa [NOME]". O usuário pode continuar o cadastro mesmo assim — não é um bloqueio hard.

Fluxo de Submit — handleSave

Mode: create

supabase.from('empresas').insert({ nome: nomeMaiusculo, nome_fantasia: nomeMaiusculo, razao_social, cnpj, categoria_id, nome_variacoes, enderecos_empresa, processavel, ativo, inativo_motivo, observacoes, organizacao_id, status_aprovacao: 'aprovada', criado_por: 'humano', aprovado_por_user_id: user.user_id, }) // RETURNING id obrigatório

Mode: edit

supabase.from('empresas') .update({ ...payload }) .eq('id', empresa_id) .eq('organizacao_id', orgId)

Mode: approve

// Cenário A: empresa já existe (empresa_id != null) → UPDATE supabase.from('empresas') .update({ ...payload }) .eq('id', empresa_id) // Cenário B: empresa nova criada pela IA (empresa_id === null) → INSERT supabase.from('empresas').insert({ ...payload, criado_por: 'ia', status_aprovacao: 'aprovada', }) // Em ambos os casos: atualizar fila supabase.from('empresas_aprovacao').update({ status: 'aprovado', aprovado_por_user_id: user.user_id, processado_por_user_id: user.user_id, processado_em: new Date().toISOString(), }).eq('id', aprovacao_id)

Invalidações após Submit

queryClient.invalidateQueries(['empresas']) queryClient.invalidateQueries(['empresas-lista']) queryClient.invalidateQueries(['empresas-fila-pendentes']) queryClient.invalidateQueries(['empresas-pendentes-count']) queryClient.invalidateQueries(['empresas-kpis'])

Backend — Schema SQL Completo

Tabela: empresas

id UUID DEFAULT gen_random_uuid() PRIMARY KEY organizacao_id UUID NOT NULL REFERENCES organizacoes(id) nome TEXT NOT NULL -- sempre uppercase (= nome_fantasia) nome_fantasia TEXT -- uppercase razao_social TEXT -- uppercase cnpj TEXT -- formato: 00.000.000/0000-00 categoria_id UUID REFERENCES empresas_categorias(id) processavel BOOLEAN DEFAULT FALSE -- pode ser ré em processos ativo BOOLEAN DEFAULT TRUE status_aprovacao TEXT CHECK (status_aprovacao IN ('pendente', 'aprovada', 'descartada_tecnico')) criado_por TEXT CHECK (criado_por IN ('humano', 'ia')) enderecos_empresa JSONB -- [{ cep, estado, cidade, endereco }] nome_variacoes JSONB -- string[] (max 20) inativo_motivo TEXT observacoes TEXT analise_ia TEXT aprovado_por_user_id UUID REFERENCES users(id) aprovado_em TIMESTAMPTZ created_by_id UUID REFERENCES users(id) deleted_at TIMESTAMPTZ -- soft delete created_at TIMESTAMPTZ DEFAULT now() updated_at TIMESTAMPTZ DEFAULT now()

Tabela: orgaos_restritivos

id UUID DEFAULT gen_random_uuid() PRIMARY KEY organizacao_id UUID NOT NULL REFERENCES organizacoes(id) nome TEXT NOT NULL cnpj TEXT processavel BOOLEAN DEFAULT FALSE ativo BOOLEAN DEFAULT TRUE enderecos JSONB -- [{ estado, cidade, endereco }] deleted_at TIMESTAMPTZ -- soft delete created_at TIMESTAMPTZ DEFAULT now() updated_at TIMESTAMPTZ DEFAULT now()

Tabela: empresas_aprovacao

id UUID PRIMARY KEY organizacao_id UUID empresa_id UUID REFERENCES empresas(id) -- NULL se empresa nova da IA status TEXT -- 'pendente' | 'aprovado' | 'descartado' score_blocos JSONB -- { total, cnpj, nome, endereco, ... } frequencia_30d INTEGER frequencia_90d INTEGER cnpj_snapshot TEXT orgao_nome TEXT uf_restricao TEXT categoria_sugerida_id UUID nome_original_snapshot TEXT aprovado_por_user_id UUID processado_por_user_id UUID processado_em TIMESTAMPTZ created_at TIMESTAMPTZ

Tabela: empresas_categorias

id UUID PRIMARY KEY organizacao_id UUID NOT NULL nome TEXT NOT NULL ativa BOOLEAN DEFAULT TRUE empresas_vinculadas JSONB created_at TIMESTAMPTZ

RPC: rpc_buscar_empresa_similar

-- Parâmetros p_organizacao_id UUID p_nome TEXT p_threshold NUMERIC -- default 0.5 (trigram similarity mínima) -- Algoritmo: pg_trgm trigram similarity -- Exclui: deleted_at IS NOT NULL -- Retorno { id, nome_fantasia, cnpj, similaridade } -- similaridade: 0.0 a 1.0

Gaps & Pendências

#ItemStatusDetalhe
G-01 Import CSV sem ViaCEP Gap Ao importar empresa com CNPJ via CSV, endereços NÃO são preenchidos automaticamente. Usuário deve editar cada empresa manualmente após o import.
G-02 RPC depende de pg_trgm Gap rpc_buscar_empresa_similar requer extensão pg_trgm. Se não instalada, a busca de similares falha silenciosamente — usuário não vê erro, popup de duplicidade nunca aparece.
G-03 score_blocos não documentado formalmente Gap Estrutura JSONB inferida pelo uso: { total, cnpj, nome, endereco, ... }. Campos específicos e algoritmo de cálculo não possuem spec formal.
G-04 ModalMergeEmpresa não coberto Fora do escopo Funcionalidade de merge existe e é acessível da fila e do card. Lógica interna (quais dados prevalecem, audit trail) não está documentada neste documento.
G-05 empresas_aprovacao com empresa_id null Tratado Quando a IA detecta uma empresa totalmente nova (não existe no banco), empresa_id=null na fila. No approve, o submit cria um INSERT novo em vez de UPDATE. Fluxo implementado em handleSave.
G-06 CopyableCNPJ — componente shared Implementado Componente shared usado no CardEmpresaGrande. Copia CNPJ formatado para clipboard com feedback visual (ícone muda por ~2s). Sem dependência de biblioteca externa.
✓
Implementado Itens G-05 e G-06 — sem ação necessária
⚠
Gaps G-01, G-02, G-03 — requerem atenção ou decisão de backlog
ℹ
Fora do escopo G-04 (merge) — documentar separadamente
