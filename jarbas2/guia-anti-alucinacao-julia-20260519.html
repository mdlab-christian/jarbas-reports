System Prompt Composition

SOUL.md + STYLE.md + skill ativa da fase atual. Quando fase = indefinido, Claude recebe apenas SOUL + STYLE sem constraints de skill — maior vetor de risco do sistema.

8 Principios Anti-Alucinacao — Qualquer Agente IA

P-01
Temperature e o controlador de criatividade
0.0–0.2: scripts, formularios, marcadores, classificacoes
0.3–0.5: conversacao com constraints fortes
0.7–1.0: NUNCA para agentes de atendimento juridico

Quanto mais consequencia tiver a saida, mais baixa deve ser a temperature.
P-02
Prompt Anchoring — nunca deixe o modelo "decidir"
Mau: "Responda adequadamente ao lead"
Bom: "Se fase=aguardando_id E docAnalysis.legivel=true → responda EXATAMENTE: [template]"

O modelo deve executar logica pre-definida, nao inventar logica propria.
P-03
Saidas estruturadas > saidas em prosa para decisoes
Para decisoes com efeitos (marcadores, fase, classificacoes): exigir JSON output. Validar o JSON antes de executar qualquer efeito colateral. Prosa livre apenas para a resposta ao usuario final.
P-04
Context Grounding — ancorar nos dados reais
Confiar: dados do banco (leads, procuracoes, memoria_julia)
Semi-confiavel: APIs externas — injetar com aviso de possivel erro
Perigoso: "implique do historico" — nunca fazer isso

O que o lead DIZ nao e fonte de verdade para dados estruturais.
P-05
Forbidden Filter como ultima linha de defesa
Rodar em TODA saida antes de enviar ao WhatsApp, independente da fase ou skill ativa. Patterns obrigatorios para agentes juridicos: garantias, prazos inventados, probabilidades, aconselhamento, inventar dados.
P-06
State Machine explicita com escape hatch
Cada agente deve ter fases com: skills ativas por fase, transicoes permitidas e proibidas, marcadores permitidos por fase, escape hatch para estado desconhecido → skill mais conservadora. Nunca um estado sem skill.
P-07
Pre-condition checks antes de marcadores de alto impacto
Marcadores com efeitos irreversiveis (criar cliente, arquivar lead, disparar auditoria) exigem multiplas pre-conditions verificadas em codigo TypeScript, nao em prompt. O modelo propoe, o codigo valida e executa.
P-08
Testes de regressao para cada alucinacao mapeada
Para cada cenario: criar conversa sintetica de teste. Rodar antes de cada deploy de mudanca no system prompt. Smoke test obrigatorio: os 5 marcadores de alto impacto so emitem nas condicoes corretas.

Forbidden Filter — 8 Patterns Criticos a Adicionar

Adicionar em forbidden-filter.ts. Rodar em TODA saida antes do envio para o WhatsApp, sem excecao de fase.

Sev Categoria Pattern (RegEx) Exemplo bloqueado
P0 Garantias /(garanto|garantimos|certeza|100%|com certeza)/i "Garanto que seu nome sera limpo"
P0 Prazos inventados /(em \d+ dias|em ate \d+|dentro de \d+)/i "em 30 dias voce tera resposta"
P0 Probabilidades /(chance(s)? de ganhar|probabilidade|provavel)/i "tem grande chance de ganhar"
P0 Credor inventado /(banco|credora?|empresa).{0,30}(costuma|tende|geralmente)/i "o Banco X costuma negociar"
P1 Aconselhamento /(voce deveria|recomendo que voce|meu conselho)/i "recomendo que voce aceite o acordo"
P1 Inventar dados /(provavelmente (deve|vai|ira)|creio que|imagino que)/i "provavelmente deve ser negativacao do Serasa"
P1 Media temporal /(em media|normalmente|geralmente|costuma) (levar|demorar|resolver)/i "em media costuma levar 6 meses"
P2 Resultado processo /(processo.{0,20}(ganhar|vencer)|indenizacao.{0,20}(certa|garantida))/i "o processo ja esta praticamente ganho"
// forbidden-filter.ts — implementacao recomendada const FORBIDDEN_PATTERNS: Array<{ pattern: RegExp; categoria: string; severidade: 'P0' | 'P1' | 'P2'; }> = [ { pattern: /(garanto|garantimos|certeza|100%|com certeza)/i, categoria: 'garantias', severidade: 'P0' }, { pattern: /(em \d+ dias|em at[eé] \d+|dentro de \d+)/i, categoria: 'prazos', severidade: 'P0' }, { pattern: /(chance(s)? de ganhar|probabilidade|prov[aá]vel)/i, categoria: 'probabilidades', severidade: 'P0' }, { pattern: /(banco|credora?|empresa).{0,30}(costuma|tende|geralmente)/i, categoria: 'credor', severidade: 'P0' }, { pattern: /(voc[eê] deveria|recomendo que voc[eê]|meu conselho)/i, categoria: 'aconselhamento', severidade: 'P1' }, { pattern: /(provavelmente (deve|vai|ir[aá])|creio que|imagino que)/i, categoria: 'inventar', severidade: 'P1' }, { pattern: /(em m[eé]dia|normalmente|geralmente|costuma) (levar|demorar|resolver)/i, categoria: 'media_temporal', severidade: 'P1' }, { pattern: /(processo.{0,20}(ganhar|vencer)|indeniza[cç][aã]o.{0,20}(certa|garantida))/i, categoria: 'resultado', severidade: 'P2' }, ]; export function applyForbiddenFilter( text: string, leadId: string ): { blocked: boolean; reason?: string; fallback?: string } { for (const { pattern, categoria, severidade } of FORBIDDEN_PATTERNS) { if (pattern.test(text)) { logAlucinacao({ leadId, categoria, severidade, trecho: text.match(pattern)?.[0] }); return { blocked: true, reason: categoria, fallback: 'Posso te ajudar com informacoes sobre seu caso. Pode me contar mais?' }; } } return { blocked: false }; }

Pre-conditions dos Marcadores de Alto Impacto

⚡
Regra absoluta: o modelo propoe, o codigo valida Nenhum marcador com efeito irreversivel deve ser executado sem verificacao de pre-conditions em codigo TypeScript. O system prompt nao e suficiente como unico guard.
// Pre-conditions para [AUDITORIA_AUTORIZADA] function validateAuditoriaPreConditions(memoria: MemoriaJulia): void { if (memoria.fase !== 'documentos_completos') throw new Error(`Auditoria bloqueada: fase incorreta (${memoria.fase})`); if (!memoria.doc_id_recebido) throw new Error('Auditoria bloqueada: doc_id nao recebido'); if (!memoria.doc_comprovante_recebido) throw new Error('Auditoria bloqueada: comprovante nao recebido'); if (memoria.auditoria_realizada) throw new Error('Auditoria bloqueada: ja realizada (idempotencia)'); } // Pre-conditions para [ARQUIVAR_LEAD] function validateArquivarPreConditions(memoria: MemoriaJulia, ultimaMsg: string): void { if (memoria.fase !== 'confirmando_cancelamento') throw new Error('Arquivar bloqueado: fase nao e confirmando_cancelamento'); const CONFIRMACAO_EXPLICITA = /(sim|quero cancelar|nao quero mais|pode cancelar|encerrar)/i; if (!CONFIRMACAO_EXPLICITA.test(ultimaMsg)) throw new Error('Arquivar bloqueado: sem confirmacao explicita do lead'); } // Uso no parser de marcadores switch (marcador) { case 'AUDITORIA_AUTORIZADA': validateAuditoriaPreConditions(memoria); await triggerAuditoria(lead); break; case 'ARQUIVAR_LEAD': validateArquivarPreConditions(memoria, ultimaMensagem); await arquivarLead(lead.id); break; }
