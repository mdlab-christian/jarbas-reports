Arquitetura da operação atual — visão geral

A operação roda em 3 máquinas físicas, cada uma com papel claro:

💻 MacBook Pro M3

Master CTO. Onde eu (Christian) opero. Comanda Air e Mini via SSH e command-bus.

💻 MacBook Air M4

Worker dedicado pro agente pessoal (Jarbas 2.0). Sim, comprei um Mac inteiro só pra ele — com livre acesso ao sistema.

🖥️ Mac Mini M4

Server multi-usuário 24/7. Hospeda 5 agentes em 5 users macOS separados. LAN + Tailscale.

Princípio central da arquitetura: cada super agente roda em um usuário macOS dedicado no Mac Mini. Isso dá isolamento de processos, sandbox de filesystem, permissões separadas e logs separados.

Funciona como se cada agente tivesse seu próprio computador — mas tudo numa mesma máquina física barata.

Como os agentes conversam entre si

Cada agente expõe uma porta HTTP no Tailscale (VPN privada criptografada entre os 3 Macs).

  • Cecília detecta intimação urgente → manda mensagem pra MIA via porta 18797 → MIA escala via Telegram pro advogado responsável.
  • OlivIA recebe pedido de geração no MdFlow → consulta Cecilia pra checar se há intimação relevante → busca jurisprudência no RAG pgvector → gera peça.
  • Jarbas pode invocar qualquer agente via SSH (ssh mac-mini-tail "cmd") ou via API local.
  • Tudo offline-first: se o Mac Mini desliga, cada agente reinicia sozinho via LaunchAgent macOS quando a máquina volta.
A conversa entre agentes usa um envelope JSON canônico com request_id, contexto, organizacao_id, data. Mesmo padrão que uso no MdFlow ↔ n8n.

Por que estou olhando pro Hermes

O que falta na operação atual e que o Hermes resolve:

  1. Skills hoje são manuais. Eu (ou Claude Code via /skill) escrevo cada uma. Hermes cria sozinho ao observar padrões repetidos (regra dos 3x automatizada).
  2. OlivIA usa só Sonnet 4.6 em tudo. Visão, busca semântica, raciocínio — mesmo modelo caro pra tudo. Hermes divide: Sonnet (raciocínio) + GPT-5-nano (busca) + Haiku (compressão/validação). Economia projetada: 40-60%.
  3. Pipeline Cecilia depende de scripts Node específicos. Hermes oferece sandbox Singularity de fábrica + cron em linguagem natural ("toda terça às 10h, gera relatório de intimações da semana").
  4. Jarbas não aprende sozinho com o uso. Hermes tem self-improving loop: a cada ~15 tool calls, reflete e cria/refina skill. Memória cross-sessão via Honcho dialectic user modeling.
  5. Migração tradicional exige reescrita. Hermes tem hermes claw migrate que importa OpenClaw inteiro em segundos — persona, memórias, skills, allowlist, API keys, plataformas. Plug-and-play.

O que NÃO vou migrar (transparência)

Regra de ouro: migrar 100% raramente é a resposta certa. Tem coisa calibrada que fica onde está.

  • Julia v2 — não é OpenClaw. É serviço Express custom + Cloudflare Tunnel + APIFULL + forbidden filter validado em produção real (com leads pagantes).
  • Pipeline-v4 da OlivIA (Node) — server.mjs lida com pgvector, prompt cache, Boris validator. Não é "skill", é engenharia específica do domínio jurídico.
  • Workers A/B/C da Cecilia — calibração da taxonomia A-G foi validada manualmente com José (audio-23 FAQ). Drift na classificação = trabalho perdido na revisão humana.
  • Cenários n8n (>80) — separação de concerns: Hermes é agente, n8n é workflow visual. Cada um no seu quadrado.

Lições compartilháveis pra comunidade

1. Isolamento por usuário macOS

É o padrão profissional. Cada agente em UID separado = segurança, observabilidade, restart isolado. Brincar de container quando você tem macOS de fábrica fazendo isso é over-engineering.

2. Pull-based > webhook em pipelines críticos

Resilência: se o Mac reinicia, o agente retoma jobs pendentes na tabela. Webhook perdido = trabalho perdido. Pull lê estado, não evento.

3. Vault como SSOT, Supabase como state

Obsidian Sync cross-Mac é o segredo do hot-reload sem deploy. Edita prompt no celular → propaga pro Pro, Air, Mini em 30s. Banco guarda só dado transacional.

4. Migrar 100% raramente é a resposta

Adicione camada nova, deixe a calibrada onde está. Os agentes que mais geram receita (Julia, Cecilia) são os últimos a tocar.

5. Multi-agent precisa protocolo

Cecília → MIA → OlivIA via portas Tailscale + envelope JSON canônico (request_id, contexto, data). Sem isso vira espaguete.

6. Self-hosted > SaaS para core agents

Dado de cliente jurídico não pode sair da casa. Self-hosted dá auditoria, LGPD compliance e custo previsível. Hermes nasceu pra isso.
