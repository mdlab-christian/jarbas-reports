Bugs P0 — Bloqueantes de Produção

BUG-01 hdnNumDocumentos=0 não retorna erro P0 · linha 2806
Após click em #btnEnviarArquivos, quando hdnNumDocumentos === '0' o sistema gera apenas um aviso e o workflow continua para E8. O lote é marcado como concluido com CNJ null — falso positivo silencioso.
// ATUAL (linha 2806) — BUG: continua mesmo com 0 documentos await logEvento(lote_id, "E7", "upload_verificacao", numDocs.hdnNumDocumentos > '0' ? "ok" : "aviso", {...}); // Workflow continua para E8 mesmo com 0 documentos // CORRETO const hdnVal = parseInt(numDocs.hdnNumDocumentos ?? '0', 10); if (hdnVal === 0) { await logEvento(..., "erro", { motivo: "zero_docs_apos_upload" }); return { ok: false, fase_falha: "E7", erro: "Nenhum documento enviado ao EPROC" }; }
Impacto: Lote marcado como concluido + CNJ null. Processo "distribuido" sem existir no EPROC.
BUG-02 String comparison em hdnNumDocumentos P0 · linha 2806
hdnNumDocumentos > '0' realiza comparação de string, não inteiro. Em JavaScript, '10' > '9' retorna false (comparação lexicográfica). Upload com 10+ documentos pode ser considerado falha silenciosa.
// BUG: '10' > '9' = false (string comparison!) numDocs.hdnNumDocumentos > '0' // CORRETO: parse para inteiro antes de comparar parseInt(numDocs.hdnNumDocumentos ?? '0', 10) > 0
Impacto: Lotes com 10+ documentos avaliados incorretamente. Bug mascara uploads bem-sucedidos.
BUG-03 Dialog handler aceita sem validar conteúdo em E8 P0 · linhas 2857-2862
O dialog "Existe arquivo selecionado não enviado" é capturado e aceito automaticamente. O workflow continua sem retornar erro mesmo quando o EPROC bloqueia o ajuizamento. O EPROC rejeita mas a Mia ignora.
// ATUAL (linha 2860) — aceita qualquer dialog sem verificar conteúdo await dialog.accept().catch(() => {}); // CORRETO — verificar mensagem antes de aceitar const msg = dialog.message().slice(0, 300); if (/existe.*arquivo.*n.o.*enviado|nenhum\s*documento/i.test(msg)) { await dialog.dismiss().catch(() => {}); return { ok: false, fase_falha: "E8", erro: `EPROC bloqueou: ${msg}` }; } await dialog.accept().catch(() => {});
Impacto: Ajuizamento rejeitado pelo EPROC mas lote marcado como concluido. CNJ nunca gerado.

Bugs P1 — Risco de Dados Incorretos

BUG-04 fleValue.value falso positivo P1 · linha 1012
ok: !!fleValue.value retorna true se value for string com apenas espaços (ex: ' '). Upload pode ser considerado bem-sucedido mesmo sem arquivo real selecionado.
// BUG: string com espaços passa na verificação return { ok: !!fleValue.value, ... }; // CORRETO: verificar conteúdo não-vazio return { ok: fleValue.value?.trim().length > 0, ... };
BUG-05 Código hardcode de documento não validado P1 · linhas 616-618
Códigos 176 (Christian/COMPROVANTES) e 262 (Heloísa/Anexo) são usados diretamente sem verificar se existem na sessão EPROC atual. Se o código não existir, o tipo de documento fica errado silenciosamente.
// BUG — linha 616: usa código sem validar existência no EPROC if (info.code) { await injetarCodigo(info.code, info.nome); return { ok: true, via: 'code', code: info.code }; // nunca verifica se foi aceito }
Impacto: Processo ajuizado com tipo de documento errado no EPROC. Não há alerta — parece ok na Mia.
BUG-06 Processo fica em "em_distribuicao" se ok=false P1 · queue-consumer linhas 176-183
Quando o adapter retorna {ok: false} sem o campo screenshot_mode, o else branch não é executado e o processo fica travado em etapa_distribuicao = "em_distribuicao" indefinidamente.
// ATUAL — BUG: else só executa se screenshot_mode explicitamente false } else if (r.screenshot_mode) { // mantém em_distribuicao } else { // só reseta se screenshot_mode está presente e é false } // CORRETO — sempre resetar quando ok=false } else { await supa.from("processos") .update({ etapa_distribuicao: "aguardando" }) .eq("id", processo_id); }
Impacto: Processo travado em "em_distribuicao" — nunca retorna para a fila. Bloqueia redistribuição.
BUG-07 Contaminação de sessão EPROC entre lotes P1 · linha 1240
persistent: true no login preserva cookies entre lotes. Se lote anterior falhou em E7 com documentos orphan, próximo lote do mesmo OAB pode herdar documentos pendentes na página. Agravado com PARALLELISM > 1.
Mitigação atual: limpeza de docs pré-existentes em E7 (linhas 2450-2527). Mas com PARALLELISM > 1, dois lotes do mesmo OAB executando em paralelo podem interferir mutuamente na limpeza.
Recomendação: Garantir PARALLELISM=1 por OAB, ou usar browsers isolados por lote.

Bugs P2 — Riscos Controlados

BUG-08 Anti-repeat bypassa se lote cancelado manualmente P2 · linhas 1088-1100
Anti-repeat só bloqueia se status = "concluido". Se operador cancelar lote A via UPDATE direto (status → cancelado) e criar lote B, o mesmo processo pode ser distribuído duas vezes no EPROC.
-- Brecha: trocar status bypassa o bloqueio UPDATE distribuicao_lotes SET status = 'cancelado' WHERE id = 'lote_a'; -- Lote B para o mesmo processo → anti-repeat NÃO bloqueia
Recomendação: Adicionar verificação de CNJ no processo — se numero_cnj IS NOT NULL, recusar novo lote.
BUG-09 nomeParaEproc vs eprocSafeNome — lógica duplicada e inconsistente P2 · linhas 257 vs 408
Duas funções de nome de arquivo com lógica diferente. Para nome "A - B": nomeParaEproc gera "A-.-B" enquanto eprocSafeNome gera "A.B".
// nomeParaEproc (linha 257) — remove APENAS espaços replace(/ /g, sep) // eprocSafeNome (linha 408) — remove espaços, traços E underscores replace(/[-_ ]+/g, sep) // Resultado para "A - B": nomeParaEproc → "A-.-B" (traço no nome original vira separador duplo) eprocSafeNome → "A.B" (traço removido corretamente)
Recomendação: Unificar em uma única função canônica — usar lógica de eprocSafeNome.
BUG-10 Competência null não bloqueia workflow P2 · linhas 1443-1445
Se nenhuma competência bate para a cidade, competenciaSel = null é logado como aviso e o workflow continua. EPROC pode rejeitar E3→E4 com erro 500, causando falha tardia e difícil de diagnosticar.
// ATUAL — null vira aviso, workflow continua if (!competenciaSel) { await logEvento(..., "aviso", { cidade }); // continua! } // CORRETO — bloquear na fase E3 if (!competenciaSel) { return { ok: false, fase_falha: "E3", erro: `Competência não encontrada para cidade: ${cidade}` }; }
Recomendação: Tratar competência null como erro P0 na hierarquia de falhas — ver tabela abaixo.

Por que remover R$ X.XXX,XX? (Fix v5)
O servidor EPROC converte LETRA + DÍGITO_ÚNICO + PONTO em LETRA ESPAÇO DÍGITO no path interno. Isso causa falha em cadastra_documento com "Falha no envio".
// Exemplo do problema descoberto no lote 8296477a: "R5.160.00" → servidor converte → "R 5.160.00" // Caminho no EPROC fica inválido — upload falha // Fix v5: remover o padrão R$ X.XXX,XX completo antes de processar nome.replace(/R\$?\s*[\d.]+,\d{2}/g, '')
Tentativa intermediária (lote 49412853): remover ponto entre letra e dígito → ainda falhou. Fix definitivo v5: remover o valor monetário completo.

Onde a Mia Se Perde — Gaps de Instrução

GAP-01
Sem CNJ após E9: Adapter retorna ok: true mas salva numero_cnj = null. Processo fica como "distribuido" mas sem CNJ no banco. Não há alerta, nenhum log de erro, nenhuma notificação para o operador.
GAP-02
Lote concluido + CNJ null = falso positivo: O queue-consumer marca etapa_distribuicao = "distribuido" mas o processo não existe no EPROC. A Mia reporta sucesso e ninguém detecta o problema sem consulta manual ao EPROC.
GAP-03
Competência fallback silencioso: Linha 1443 usa fallback: true sem alertar. Processo pode ser distribuído para foro errado — tribunal aceita mas a competência no EPROC fica incorreta para a causa.
GAP-04
Réu cadastrado como PJ mesmo sendo ENT: Para Boa Vista, Banrisul e similares no RS, o EPROC usa o tipo "Entidade" (ENT), não PJ. Se o matching por CNPJ falhar, o adapter pode cadastrar o réu como PJ incorretamente — processo ajuizado com parte errada.
GAP-05
Upload via setInputFiles vs POST direto — diagnóstico cego: Quando setInputFiles não dispara o upload automático do Fine Uploader (autoUpload=false no EPROC), o adapter usa POST direto via page.context().request.post(). Esse POST bypassa o browser e NÃO é capturado por page.on('request'), tornando impossível rastrear falhas de upload por interceptação de rede.
