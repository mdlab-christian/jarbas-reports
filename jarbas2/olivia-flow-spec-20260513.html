OlivIA Flow

Fila de lote para preparação de petições. O time manda N processos para análise de uma vez. Quando prontos, cada processo abre direto no VibeLaw no Step 2 — tópicos já gerados, revisão na hora.

🔒 Decisões Fechadas

Todas confirmadas — sem bloqueios antes de implementar.

D-01
Onde roda o mecanismo de geração?
Mac Mini — sem mudança. O Flow não toca no mecanismo. Mesmo pipeline, mesmas Edge Functions.

D-02
Quantas abas simultâneas?
10 tabs. Constante OLIVIA_MAX_TABS = 10 já está no código — nada a mudar.

Qual é o escopo do Flow?
Flow = Step 1 em lote. Após análise, usuário abre no VibeLaw já no Step 2 (tópicos prontos). Steps 2–4 são idênticos ao VibeLaw atual.
Só Step 1 em lote
D-04
Tratamento de erro durante geração?
Healthcheck do Mac Mini antes de iniciar. Se offline, o item entra em fila mas não dispara. Toast de aviso.

🔑 O segredo técnico: apenas 2 linhas novas no store

Quando o usuário clica "Abrir no VibeLaw", o Flow simplesmente chama addTab('vibelaw') e logo depois updateWizardState(tabId, { historicoId, stepId: 'topicos', processo, tipoPeticaoId, advogadoId }). O usePeticaoStore já suporta isso — o wizard VibeLaw abre direto no Step 2 porque completedSteps inclui 'identificacao' quando processo.id e tipoPeticaoId estão preenchidos. Zero refactor no VibeLaw.

🏗️ Arquitetura Técnica — O que é novo vs reutilizado

O Flow não cria nada novo no backend. Toda a complexidade nova é frontend.

✅ REUTILIZADO (zero mudança)
olivia-topicos EF olivia-gerar EF olivia_historico table usePeticaoStore useOliviaStatusRealtime SearchBoxProcesso SeletorTipoPeticao AdvogadoSelector NivelQualidadeIaRadio UploadDocumentosV3 Step1InstrucoesIa Mac Mini pipeline addTab('vibelaw') updateWizardState
🆕 NOVO (só frontend)
FlowPage.tsx FlowAddPanel.tsx FlowQueueGrid.tsx FlowProcessCard.tsx FlowBatchSelector.tsx useFlowQueue.ts useFlowRealtime.ts flowStore (Zustand slice) rota /olivia/flow
Como o Flow usa olivia_historico (sem nova coluna)
Campo existente Usado pelo Flow como Novo?
id Identificador do item na fila. O FlowProcessCard o usa para a subscription Realtime e para chamar updateWizardState({ historicoId }) ao abrir no VibeLaw. Reutiliza
status PENDENTE → na fila · PROCESSANDO → analisando · CONCLUIDO → pronto · ERRO → falhou. Já existia — Flow só lê. Reutiliza
etapa_atual Monta o label da progress bar: "S3 — Buscando jurisprudência". Já existia (T02 da oliviav4). Reutiliza
topicos_gerados Quando preenchido → contagem de tópicos no card "Pronto" ("7 tópicos"). Reutiliza
analise_score Exibido no card "Pronto" como score sintético (ex: "8.7"). Reutiliza
processo_id, tipo_peticao_id, advogado_id, nivel_qualidade_ia Dados submetidos pelo Flow para criar o historico_id. Mesmo payload do Step 1 VibeLaw. Reutiliza
origem (TEXT) Flow seta origem = 'flow' para diferenciar no Histórico de petições. Campo já existe, valor novo. Valor novo
🧩 Componentes Novos — Detalhamento

Apenas os componentes que precisam ser criados. Nada mais.

FlowPage.tsx
Entry point da rota /olivia/flow. Layout bipartido: FlowAddPanel (esq) + FlowQueueGrid (dir). Gerencia toggle Individual/Lote. Passa onAbrirVibeLaw para os cards.
CRIAR
FlowAddPanel.tsx
Sidebar esquerda. Importa e renderiza diretamente os componentes do Step 1: SearchBoxProcesso, SeletorTipoPeticao, AdvogadoSelector, NivelQualidadeIaRadio, UploadDocumentosV3, Step1InstrucoesIa. Botão "Adicionar à Fila" chama useFlowQueue.addItem().
CRIAR · reutiliza Step 1
FlowBatchSelector.tsx
Modo Lote. Lista de processos com checkbox de multi-seleção. Busca via SearchBoxProcesso adaptado (lista em vez de único). Configuração única (tipo, advogado, qualidade) aplicada a todos os selecionados.
CRIAR
FlowQueueGrid.tsx
Área principal. Grid responsivo de FlowProcessCard. Tabs de filtro (Todos / Na Fila / Analisando / Prontos / Erros). Ordenação: analisando primeiro, depois prontos, depois fila.
CRIAR
FlowProcessCard.tsx
Card individual. 4 estados visuais: na_fila (posição na fila), analisando (progress bar com etapa do Realtime), pronto (score + botão VibeLaw), erro (mensagem + retry). Subscription Realtime própria via useFlowRealtime(historicoId).
CRIAR
useFlowQueue.ts
Hook central. Gerencia flowItems[] (lista de { id, historicoId, processoId, tipoPeticaoId, advogadoId, status }). addItem() chama EF olivia-topicos e salva historicoId no estado. removeItem(). openInVibeLaw(historicoId) chama addTab + updateWizardState.
CRIAR
useFlowRealtime.ts
Subscription Realtime em olivia_historico filtrado por id=eq.{historicoId}. Expõe { status, etapa_atual, analise_score, topicos_count }. Wrapper fino sobre o useOliviaStatusRealtime existente.
EXTENDE existente
flowStore (Zustand slice)
Slice Zustand para persistir a fila no localStorage (survive refresh). Armazena: items[] com todos os dados necessários para recriar os cards. Items com status PRONTO ficam 24h; ERRO ficam até dismiss manual.
CRIAR · slice do store
Rota /olivia/flow
Adicionada no React Router. Protegida para perfis juridico e admin. Entrada no menu lateral de OlivIA como tab "Flow" ao lado de "Gerador" e "Histórico".
CRIAR · 5 linhas
🚀 Implementação — 5 Fases

Ordem de execução que minimiza retrabalho e valida cada fase antes da próxima.

1
Rota + Layout base — 1h
Criar /olivia/flow no router. FlowPage.tsx com o layout bipartido (sidebar 300px + main flex-1). Adicionar entrada "Flow" no menu/tabs de OlivIA. Sem funcionalidade ainda — só estrutura.
2
FlowAddPanel (modo Individual) + useFlowQueue — 3h
Importar os componentes do Step 1 existentes no FlowAddPanel. Criar o useFlowQueue com addItem() que chama olivia-topicos EF e persiste no Zustand slice (flowStore). Botão "Adicionar à Fila" funcional.
3
FlowQueueGrid + FlowProcessCard (4 estados) + useFlowRealtime — 4h
Grid de cards com filtros. FlowProcessCard com os 4 estados visuais. useFlowRealtime wrappando useOliviaStatusRealtime. Progress bar atualiza ao vivo. Card muda de estado quando Realtime dispara.
4
"Abrir no VibeLaw" → Step 2 — 1h
No useFlowQueue.openInVibeLaw(historicoId): (1) const tabId = addTab('vibelaw'), (2) updateWizardState(tabId, { historicoId, stepId: 'topicos', processo, tipoPeticaoId, advogadoId }), (3) navigate('/olivia'). Testar com processo real — deve abrir direto no Step 2 com tópicos carregados.
5
Modo Lote (FlowBatchSelector) — 3h
Toggle Individual/Lote no FlowAddPanel. FlowBatchSelector com lista de processos (query paginada), checkboxes de multi-seleção, configuração única (tipo, advogado, qualidade). Botão "Enviar N para Análise" faz loop de addItem() para cada selecionado.
⚠️ Atenção: concorrência de análises

O Mac Mini processa uma análise por vez (pipeline síncrono). Se o usuário enviar 8 processos em lote, os 8 vão criar olivia_historico com status PENDENTE. A EF olivia-topicos já tem lógica de fila sequencial? Verificar antes de implementar. Se não tiver, o Flow precisa disparar a análise do próximo item via Realtime quando o anterior virar CONCLUIDO — lógica simples no useFlowQueue. A UI já mostra "Posição N" nos cards na fila, preparada para isso.

✨ UX Detalhada — Micro interações

O que faz a diferença na experiência diária do time.

Animações de estado
  • → Card "Na Fila" → "Analisando": border pisca verde por 0.5s, badge anima entrada
  • → Progress bar: transição suave com transition: width 0.5s ease
  • → Card "Analisando" → "Pronto": confetti sutil (framer-motion), toast discreto no topo direito
  • → Botão "Abrir no VibeLaw": pulse animation para chamar atenção
Persistência da fila
  • → Fila salva no Zustand com persist (localStorage)
  • → Refresh da página não perde os cards
  • → Cards "Prontos" expiram após 24h automaticamente
  • → Ao voltar para /olivia/flow, Realtime re-sincroniza status atual do banco
Integração com /olivia (tabs)
  • → "Abrir no VibeLaw" → navigate('/olivia') + nova tab criada
  • → Se já tem 10 tabs abertas: toast "Feche uma aba antes de abrir"
  • → Card fica como "Pronto" na fila mesmo após abrir — pode abrir de novo
  • → Badge de notificação no menu "OlivIA" quando algum processo ficar Pronto
Keyboard shortcuts
  • → Cmd+Enter no form: adiciona à fila
  • → Cmd+Shift+F: vai para /olivia/flow de qualquer página
  • → Foco automático no campo de processo ao abrir a página
Vai funcionar? Sim. E é elegante.

O Flow não reinventa nada. Ele aproveita 100% do mecanismo existente e adiciona apenas o que falta: uma interface de fila que deixa o time preparar o dia de trabalho antes de abrir o VibeLaw. Toda a complexidade nova é frontend. Estimativa: 12-15h de implementação para um MVP funcional com os 2 modos (Individual + Lote).

O único risco real é a concorrência no Mac Mini — verificar se olivia-topicos já sequencia as chamadas ou se o Flow precisa gerenciar a fila localmente. Isso define 2h a mais ou a menos na implementação.
