O que estamos fazendo

Hoje a Olivia roda no Claude web (Project + MCP remoto próprio). Vamos criar uma versão paralela no ChatGPT Business usando o mesmo servidor MCP — já deployado e testado. Nada muda no backend do MdFlow. O objetivo é rodar um piloto controlado, comparar as duas versões e decidir GO/NO-GO com a equipe.

Pacote de migração: todos os arquivos citados aqui estão na mesma pasta deste HTML — instructions-project.md, kb/ (12-15 docs), roteiro-smoke.md, resposta-brainstorm-gpt.txt e mcp/CONECTOR-URL.txt.
⚠️ Segredo: o arquivo mcp/CONECTOR-URL.txt contém a URL do conector com o token embutido. Trate como senha. Nunca cole em chat, e-mail, print ou documento público.
FASE 0 Pré-requisitos ~30 min + compra

Tudo aqui depende de decisão e verba do CTO. Não avance sem fechar os três gates.

0.1 Comprar ChatGPT Business GATE CTO ~10 min
Contratar o plano Business (ex-Team), modalidade mensal, com no mínimo 2 seats (~US$ 25-30/seat/mês) em chatgpt.com/business.
Por que Business é obrigatório: MCP com escrita só existe em Business/Enterprise. O plano Pro só permite conectores de leitura — e a Olivia precisa disparar geração de petição (write com modal).
0.2 Definir o advogado nº 2 do smoke GATE CTO ~5 min
Escolher o segundo advogado que vai testar junto com o Christian e convidá-lo para o workspace do ChatGPT Business (Settings → Members → Invite).
0.3 Avisar a equipe: conector é web-only ~2 min
Comunicar que o conector MCP custom funciona apenas no ChatGPT web. Não há suporte a conector custom no mobile — durante o piloto, todos usam o navegador.
FASE 1 Conector MCP ~15 min

Conectar o ChatGPT ao servidor MCP do MdFlow. Aqui está o teste real da decisão q2=b.

1.1 Ativar o Developer mode ~2 min
Entrar no ChatGPT web como admin do workspace → Settings → Connectors → Advanced → ativar Developer mode.
1.2 Criar o conector ~3 min
Nome: olivia-gpt-mcp-v1 — congelar esse nome. Se precisar mudar qualquer coisa depois, crie uma v2 em vez de editar. Descrição: "Olivia — backend MdFlow (perfil jurídico)".
1.3 Colar a URL e configurar a autenticação SEGREDO ~3 min
Abrir o arquivo mcp/CONECTOR-URL.txt e copiar a URL exatamente como está. Ela já leva o token de acesso embutido — trate como senha. No campo de autenticação, escolher No authentication (o token viaja na própria URL).
Não transcreva a URL em nenhum outro lugar. Copie do arquivo direto para o campo do ChatGPT.
1.4 Salvar e verificar as ferramentas ~2 min
Salvar o conector e confirmar que o ChatGPT listou ~41 ferramentas. Se listou, a conexão está correta e o perfil jurídico está ativo.
1.5 Teste-chave (decisão q2=b) TESTE-CHAVE ~2 min
Este é o teste real de que o token-na-URL funciona no ChatGPT. Se o ChatGPT recusar a URL com token ou falhar a conexão, ative o PLANO B (ver Troubleshooting): o servidor já tem OAuth 2.1 pronto — basta escolher "OAuth" no conector e logar com a conta MdFlow do advogado.
1.6 Compartilhar o conector com o workspace ~2 min
Como admin, publicar o conector para os membros do workspace, para que o advogado nº 2 consiga habilitá-lo no Project.
FASE 2 Project "OlivIA — Jurídico" ~20 min

Montar o espaço da Olivia no ChatGPT com instructions, base de conhecimento e o conector.

2.1 Criar um Project (não GPT custom) ~2 min
Criar um Project no ChatGPT chamado OlivIA — Jurídico.
Por que Project e não GPT custom: Projects no Business aceitam 40 arquivos e conversas compartilhadas da equipe. GPT custom fica como evolução futura.
2.2 Colar as instructions ~3 min
Abrir instructions-project.md, copiar tudo e colar no campo Instructions do Project. Cabe — o arquivo está em ≤ 8.000 caracteres.
2.3 Subir a base de conhecimento (KB) ~8 min
Fazer upload de todos os arquivos da pasta kb/ (12-15 arquivos) para o Project.
2.4 Habilitar o conector no Project ~2 min
Nas configurações do Project, ativar o conector olivia-gpt-mcp-v1 criado na Fase 1.
2.5 Compartilhar o Project ~2 min
Compartilhar o Project com o advogado nº 2 primeiro (para o smoke). A abertura para a equipe inteira acontece só na Fase 4, após o GO.
FASE 3 Smoke test dias 1-3

Validação prática com o Christian e o advogado nº 2 antes de abrir para a equipe.

3.1 Rodar o roteiro de smoke ~2h distribuídas
Seguir o arquivo roteiro-smoke.md — 10 testes executados por Christian + advogado nº 2.
Os 3 testes críticos
  • /peticao em 2 turnos SEM peça no chat — a REGRA MÁXIMA da Olivia. A peça nunca aparece no chat; ela é gerada no MdFlow.
  • gerar_peticao dispara no MdFlow e devolve o link do documento gerado.
  • Modal de confirmação nas writes — ensinar o clique em "aprovar e lembrar nesta conversa" para não repetir a confirmação a cada ação.
Opcional: resposta-brainstorm-gpt.txt pode ser colado no chat do GPT parceiro de planejamento para fechar o brainstorm. Não é obrigatório para o smoke.
FASE 4 Expandir para a equipe semana 2

Após o smoke aprovado, escalar para o restante da equipe e medir o piloto.

4.1 Adicionar seats e compartilhar ~15 min
Adicionar os seats necessários, compartilhar o Project e o conector com a equipe.
4.2 Mini-treinamento: 3 diferenças vs Claude ~30 min
1. Os comandos são texto simples (sem sintaxe especial).
2. O relatório vem como arquivo para download, não no corpo do chat.
3. As ações de escrita passam por modal de confirmação.
4.3 Rodar as 5 métricas e decidir GO/NO-GO DECISÃO CTO semana
Coletar as métricas do piloto e decidir a continuidade.
1. % de gerações corretas pelo MdFlow
2. Nota do relatório
3. Zero peça no chat (REGRA MÁXIMA)
4. Nº de intervenções manuais
5. Preferência da equipe (Olivia GPT vs Olivia Claude)

Troubleshooting

Problema O que fazer
Conector não lista as tools Conferir a URL exata e o token (copiar de novo do mcp/CONECTOR-URL.txt). Testar com curl é opcional para isolar se é o servidor ou o ChatGPT.
ChatGPT ignora a REGRA MÁXIMA O reforço já existe nas instructions do servidor e do Project. Se acontecer, reportar o caso no roteiro de smoke para ajuste da instrução.
Modal de confirmação toda hora Usar "lembrar aprovação" — vale por conversa. Reaparecer em conversa nova é comportamento esperado, não bug.
URL com token foi recusada (PLANO B) Trocar a autenticação do conector para OAuth → abre popup → login com a conta MdFlow do advogado. O servidor já tem OAuth 2.1 pronto.
Vazamento da URL/token Avisar o Jarbas para revogar o token Olivia-GPTPiloto e gerar outro (~1 min). Reconfigurar o conector com a nova URL.
MCP no mobile Não existe conector custom no mobile. Durante o piloto, usar ChatGPT web.
