05. Pipeline proposto polish-2005

Step 1Análise paralela por documento
Sonnet 4.6 — 1 agent por doc + consolidador. Reduz latência ~50%.
Step 2Tópicos + Score + Perguntas
Frontend popula em tempo real. Gate obrigatório: operador valida antes do Step 3.
Step 2.5Boris Batch Preparer
Carrega modelo do escritório (peticao_template + tags) → filtra jurisprudências por tag → filtra blocos texto por tag → gera spec.json com 1 prompt por seção.
Step 3GERAÇÃO PARALELA (workers Sonnet 4.6)
Agent 1: Endereçamento + Qualificação
Agent 2: Preliminares (1 a 1)
Agent 3: Estrutura probatória IF (4 sub-tópicos)
Agent 4: Origem do débito
Agent 5: Dano moral (usa bloco modelo)
Agent 6: Pedidos (usa bloco modelo)
Agent 7: Fecho + Assinatura
Step 3.5Merger determinístico (Node.js)
Concatena seções na ordem canônica → valida coerência (juris única, sem duplicação) → substitui placeholders.
Step 4Consolidador IA (Sonnet 4.6)
Aplica style guide do advogado → reescreve transições entre seções → mantém voz consistente.
Step 5Post-process
8 passes determinísticos + 18 leonardo-fixes (slot bugs, cidade por OAB, fecho assinatura, ordem canônica).

08. Smart Blocks lapidado — proposta detalhada

Como funciona:

  1. Modelo do escritório tem N tags (ex: ENDERECAMENTO, QUALIFICACAO, PRELIM_LITIG_MA_FE, IF_REQUISITOS_PROVA, IF_CARTAO_CONTRATACAO, etc)
  2. Cada tag tem 1+ blocos de texto consagrados
  3. Boris carrega modelo + filtra blocos relevantes por caso
  4. Boris cria 1 prompt por tag com:
    • Bloco consagrado (texto base)
    • Dados do caso concreto (nomes, valores, datas, partes)
    • Jurisprudências vinculadas àquela tag (whitelist)
    • Instrução: "LAPIDE este bloco aplicando os dados do caso. Mantenha estrutura e tom"
  5. Worker LAPIDA (não cria do zero)
  6. Output: HTML do bloco lapidado

Diferença vs polish-1905 livre:

❌ 1905: "Boris dá contexto, Olivia escreve livre"
✅ 2005: "Boris dá bloco base, worker LAPIDA com dados"
