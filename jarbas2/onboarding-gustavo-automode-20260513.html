Workflow Projetos em Automode

Como o Christian executa projetos grandes em automode sem intervenção humana — guia completo para você (Gustavo)

v1.0 Baseado no polish-1405 2026-05-13 user: beto · Mac Mini
📌 TL;DR — leia isso primeiro

Você nunca mais vai fazer "vibe coding". Vamos planejar TUDO juntos, investigar a fundo, deixar tudo decidido — e aí disparar o automode que executa sozinho enquanto você dorme. Este HTML te ensina cada fase com o exemplo real do polish-1405 que acabamos de fazer.

01 🧠

Princípio Anti-Vibe-Coding

Filosofia MdLab
Vibe coding = abrir o Claude Code e ir mandando ideia atrás de ideia, sem planejar. Resultado: contexto explode, código fica frankenstein, IA inventa coisas.

Workflow MdLab = planejar TUDO antes (pode levar 1 dia inteiro), depois deixar a IA executar em automode 100% sem intervenção, com gates de qualidade e loop iterativo até atingir o critério.

❌ Vibe coding

  • Caos: contexto explode em 1h
  • IA inventa schemas que não existem
  • Retrabalho gigante
  • Dívida técnica acumulada
  • Nada documentado
  • "Funciona" mas quebra em produção

✅ Automode MdLab

  • Cirúrgico: cada task isolada
  • Investigação valida tudo antes
  • Execução paralela em worktrees
  • Zero retrabalho
  • Tudo no mdlab-vault
  • Gates de qualidade impedem bug em prod

🎯 ROI prático

  • 12-15 dias humano → 8-10 dias automode
  • Você dorme, IA trabalha
  • Mesmo resultado, menos esforço
  • Repetível e replicável
  • Custo IA controlado ($20–$500)
  • Documentação grátis no fim

As 4 fases — visão geral

Todo projeto MdLab passa por estas 4 fases na ordem. Não dá para pular nenhuma.

💡 Tempo total realista
Projeto pequeno (10 tasks): 3 dias. Projeto médio: 1 semana. Projeto grande tipo polish-1405 (~140 tasks): 12–14 dias. A maior parte é Fase 1 (planejamento) + Fase 3 (automode rodando sozinho).
03 🎯

Fase 1 — Planejamento (a mais importante)

É aqui que você vai passar a maior parte do tempo. Não tenha pressa. Cada decisão bem tomada nessa fase economiza horas na execução.

3.1 · Como começar
cd ~/beta-mdflow # ou outro repo onde vai trabalhar claude --model opus-4.7 # abre Claude Code # cole o PROMPT MESTRE (Seção 8)

É só isso. Daí em diante você só conversa.

3.2 · O que você (Gustavo) faz nessa fase
  • FAZ  Conversa com Claude Code sem parar
  • FAZ  Vai jogando ideias, descobertas, mudanças de rumo
  • FAZ  A cada ideia nova, Claude investiga, documenta no vault, cria task
  • FAZ  Recebe HTML didático periódico quando há decisões pendentes
  • FAZ  Responde decisões no formato D5=A ou D-INV24-01=C

3.3 · Como decisões são apresentadas pra você

Toda decisão do Claude segue exatamente este formato. Você reconhece de longe, lê em 30 segundos, responde em 3.

🔵 D-INV24-01
Pergunta: Backfill 150 modelos com conteudo_template_html_rico vazio?
Contexto: 43% dos modelos no banco têm HTML vazio. Selector retorna NULL → "modelo sumiu" silencioso em produção.
Opções:
  A) Backfill via Sonnet 4.6 (~$450, 8h)
  B) Manter como está (43% fica lixo silencioso)
  C) Modelo legado bypass via fallback estático
✅ Recomendação: A
Por quê: sem backfill, 43% dos modelos viram lixo silencioso. Custo $450 é one-shot. ROI alto.
→ Sua resposta: "D-INV24-01=A" (3 segundos)
🎯 Padrão imutável
TODA decisão segue esse formato. Contexto + Opções + Recomendação + Por quê. Você responde só com a sigla. Não precisa explicar nada — Claude entende e aplica.

3.4 · Como criar um projeto novo no mdlab-vault

Passo a passo
  1. Você diz: "Quero criar um projeto novo"
  2. Claude pergunta: "Qual o nome? Qual o tema?"
  3. Você responde: "olivia/flow" ou "mdflow/feature-acordos-v2"
  4. Claude roda: /projeto:init olivia/flow
  5. Cria a estrutura padrão automaticamente:
~/Documents/mdlab-vault/01_projetos/_gustavo/olivia/flow/ ├── README.md # overview do projeto ├── SPEC.md # spec funcional ├── ULTRAPLAN-AUTOMODE.md # plano de execução automode ├── MAPA-NAVEGACAO-IA.md # índice para IA retomar contexto ├── decisoes/ │ └── DECISOES-CONSOLIDADAS.md # D1=A, D2=B, ... ├── consideracoes-cto/ │ ├── 01-briefing.md │ └── 02-sessao-... ├── investigacoes/ │ ├── 01-tema.md │ ├── 02-tema.md │ └── NN-tema.md └── smoke-NNN/ # se aplicável └── MATRIZ.csv

Daí em diante você só conversa. Claude documenta tudo lá automaticamente.

3.5 · TUDO vai pro mdlab-vault automaticamente

📦 Você não precisa abrir Obsidian durante a conversa
Claude salva tudo no vault em tempo real. Quando quiser revisar offline (sofá, café, fim de semana), abre o Obsidian que está tudo lá organizado em 01_projetos/_gustavo/<nome>/.

Obsidian Sync (Christian compartilhou contigo) deixa SEU mdlab-vault sincronizado com o do Christian em tempo real. Os dois veem a mesma coisa.

3.6 · Quando você for embora e voltar amanhã

Pode fechar o terminal a qualquer momento. Tudo está salvo no vault. No dia seguinte:

cd ~/beta-mdflow claude --model opus-4.7 # cola o PROMPT MESTRE # adiciona no fim: "Continue o projeto olivia/flow de onde parou"

Claude lê o MAPA-NAVEGACAO-IA.md do projeto e retoma o contexto exato. Não precisa re-explicar nada.

3.7 · Sinal de que Fase 1 acabou

Você só passa pra Fase 3 (automode) quando todos estes critérios são ✅ verde:

  • Todas as decisões D1..DN têm valor fechado (sem ? ou pendente)
  • ULTRAPLAN-AUTOMODE.md existe e está completo (waves, tasks, gates)
  • Smoke pré-automode rodou (se aplicável) — ex.: polish-1405 rodou smoke-348
  • HTML final tem 0 perguntas abertas
  • MAPA-NAVEGACAO-IA.md existe e aponta os arquivos críticos
  • Claude gerou o PROMPT DE DISPARO AUTOMODE pra você copiar
⚠️ Se algum critério está faltando
NÃO dispare o automode. Fique mais um dia na Fase 1. Falhar aqui custa muito mais caro do que demorar mais.

05 🚀

Fase 3 — Execução em Automode

🚨
Regra inviolável
Você só dispara o automode quando TODAS as decisões estão fechadas e o ULTRAPLAN está pronto. Disparar com decisão pendente = automode trava no meio.

5.1 · Como disparar

1) Abra terminal NOVO (NÃO use o do planejamento — está cheio de contexto) 2) cd ~/beta-mdflow # ou onde for 3) claude --model opus-4.7 4) Cole o PROMPT DE DISPARO AUTOMODE (Claude gerou pra você no fim da Fase 1 — está no vault) 5) Escreva: "Inicia automode <nome-projeto>" 6) FECHE O TERMINAL. Vá fazer outra coisa. Volte em 8–10 dias.

5.2 · O que acontece sem você

Olhando o polish-1405 como exemplo real:

06 ✅

Fase 4 — Revisão + Validação

Após o automode terminar, Claude entrega automaticamente:

  • HTML de relatório final (abre automático no browser)
  • Tag git <projeto>-final-PERFECT-{timestamp} com push origin main
  • Wave L canary 24h rodando em background (smoke pós-deploy contínuo)
  • Documentação final atualizada no vault
  • Custo IA totalizado e registrado

Você então:

  1. Lê o report (10 min)
  2. Valida visualmente o que mudou em produção
  3. Decide: aceita resultado ou pede correções (volta para Fase 1 ciclo 2)
🔁 Ciclo iterativo é normal
polish-1405 teve 5 iterações até atingir 18/18 PASS. Cada iteração levou 2–4h de automode. Iteração é parte do processo, não falha.
07 ⚖️

Regras Invioláveis

✅ Sempre

  • Conversar tudo com Claude antes de executar
  • Salvar tudo no mdlab-vault
  • Responder decisões no formato D1=A
  • Criar projeto com /projeto:init no início
  • Usar terminal limpo pro automode (não reaproveitar)
  • Confirmar critérios da Seção 3.7 antes do automode

❌ Nunca

  • Editar código direto sem passar pelo Claude
  • Pular fase de investigação
  • Disparar automode com decisão pendente
  • git push --force em main
  • DELETE em produção sem confirmar
  • Commitar .env com valores reais

Você é o Claude Code operando como assistente de projetos do Gustavo (advogado MdLab, user beto no Mac Mini). Esta sessão vai seguir o WORKFLOW PROJETOS EM AUTOMODE da MdLab.

4. ~/Documents/mdlab-vault/08_onboarding-gustavo/01-WORKFLOW-PROJETOS-AUTOMODE.html (este guia)

REGRAS DO WORKFLOW MDLAB:

1. ANTI-VIBE-CODING: NUNCA executar código sem planejar. Planejamento profundo > implementação rápida.

2. 4 FASES OBRIGATÓRIAS:
   - Fase 1 PLANEJAMENTO: conversamos por 1-2 dias, criamos decisões, ULTRAPLAN
   - Fase 2 INVESTIGAÇÃO: você dispara agents em background pra investigar pontos
   - Fase 3 EXECUÇÃO AUTOMODE: terminal novo, sem mim, 8-10 dias sozinho
   - Fase 4 REVISÃO: validação pós-automode

5. DECISÕES: SEMPRE apresentar como:
   🔵 D-XXX-NN — <pergunta>
   Contexto: <1-2 linhas>

     A) <opção>

7. INVESTIGAÇÕES BACKGROUND: use Task tool com `run_in_background: true` pra investigações longas. Notifique quando completar.

8. GIT: branch SEMPRE main. Commits em pt-BR `tipo(escopo): resumo`. NUNCA --force.

9. SUPABASE: produção MdFlow é `qdivfairxhdihaqqypgb`. Sempre `organizacao_id` + RLS. Operações destrutivas pedem confirmação Gustavo.

10. AUTOMODE: só inicie automode quando TODAS decisões fechadas + ULTRAPLAN completo + (se aplicável) smoke pré-automode rodou. Gere prompt de disparo pra Gustavo abrir terminal novo.

INSTRUÇÃO INICIAL:
Pergunte ao Gustavo:
1. "Você tem um projeto novo ou continua um existente?"
2. Se novo: "Qual é a ideia ou problema que você quer resolver?"
3. Se continua: "Qual o nome do projeto?" — leia o MAPA-NAVEGACAO-IA.md correspondente

Após resposta, começamos Fase 1 Planejamento. Investigamos calmamente, geramos decisões, criamos ULTRAPLAN. Só passamos pra Fase 3 quando ele aprovar.

Comece agora pedindo as respostas das 3 perguntas acima.

11 ❓

Dúvidas que você vai ter

01E se eu errar uma decisão?
Avisa o Claude: "muda D5 para B". Ele atualiza DECISOES-CONSOLIDADAS.md, recalcula impactos e refaz o ULTRAPLAN se necessário.
02E se Claude inventar algo?
O workflow força investigação antes de decisão. Se ainda assim suspeitar, manda "mostra de onde tirou isso". Ele cita arquivo:linha ou query SQL. Sem fonte = não vai pro plano.
03Posso usar pra projeto MdFlow?
Sim — qualquer projeto técnico com 5+ tasks. Não funciona pra "fazer X agora rápido" (1 task isolada). Pra isso, use Claude Code direto sem essa formalidade toda.
04Preciso do Christian em algum momento?
Só se cruzar com produção crítica (Mac Mini olivia user, super_agente, schema MdFlow core). Pra tudo do MdFlow normal e projetos do seu vault, autônomo.
05Quanto custa em IA por projeto?
Variável. Projeto pequeno: ~$20. Médio: $50–100. Grande tipo polish-1405 (~140 tasks): ~$500. Claude te avisa estimativa antes de disparar automode.
06E se o automode falhar no meio?
Recovery automático em 3 níveis: retry com Sonnet → escala pra Opus → lenient_pass. Só te notifica em P0 bloqueante (~5% probabilidade). Caso contrário, segue sozinho.
07Posso pausar o automode?
Sim, qualquer hora. Tag git baseline preservada. git reset --hard <tag-baseline> volta ao estado pré-automode em 30 segundos.
08Como vejo o resultado final?
HTML final gerado automaticamente abre no browser + tag git <projeto>-final-PERFECT-... pushed + report markdown no vault. Tudo automático.
09Preciso aprender git?
Não. Claude faz tudo (branch, commit, push, merge, tag). Você só vê os commits depois se quiser auditar. Comandos git nunca passam pela sua mão.
10E se eu não souber o que pedir?
Comece falando do problema, não da solução: "Quero melhorar X", "Tem bug em Y", "Acho que falta Z na página W". Claude faz as perguntas certas pra extrair o que precisa.
