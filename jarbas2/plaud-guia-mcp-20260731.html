Como saber se uma gravação já tem texto

heurística do nome
✅ Nome = título descritivo

Ex.: "07-29 Nota de Produto: Sistema Financeiro…"

A IA renomeou o arquivo. Isso só acontece depois da transcrição → transcrita e resumida. O MCP lê tudo: resumo, action items, transcrição por falante.

❌ Nome = timestamp cru

Ex.: 2026-07-23 20:24:55

Ninguém apertou "transcrever" → só áudio na nuvem. O MCP não tem texto nenhum, mas o MP3 existe → caminho R4 (transcrição local).

Nota técnica que muda como eu opero
get_note e get_transcript não são endpoints — são recortes locais do mesmo GET /files/{id}. O MCP chama a API uma vez e faz parsing dos blocos (transaction = transcrição crua, transaction_polish = limpa pela IA, outline = tópicos, auto_sum_note = resumo). Ou seja: eles economizam contexto, não chamadas de rede. Regra: get_file só quando eu preciso do MP3 ou checar disponibilidade — nunca em loop sobre 20 gravações.

D1

A — npx @plaud-ai/mcp install: instala plugin + 7 skills. Mexe no ~/.claude.json; skills em inglês, sem contexto MdFlow.
B — Criar skill própria /plaud no padrão Jarbas, absorvendo o que há de bom nas 7 + receitas R1–R5 + transcrição local. Custo: ~1 sessão.

Recomendação: B. As skills oficiais não sabem nada de /projeto, jarbas-vault nem do caminho mlx-whisper — que é justamente o diferencial descoberto. Uma /plaud própria entra no seu vocabulário: /plaud ultima, /plaud projeto <termo>.
D2
Política de transcrição: app ou local?
A — Sempre no app: tudo padronizado na nuvem, get_note sempre disponível.
B — Sempre local: economia máxima, nuvem Plaud vira só storage de áudio.
C — Híbrido por natureza da gravação: reunião com pessoas → app; monólogo de projeto → local.
Recomendação: C. Seu uso dominante é monólogo de projeto, onde a diarização é irrelevante e eu faço resumo melhor que o Plaud porque conheço o MdFlow. Reunião de equipe/cliente é o caso onde os minutos do plano se pagam.
D3
Captura automática de gravações novas?
A — Cron 2×/dia (09h/19h) varre novas → arquiva resumo no vault → notifica no briefing matinal.
B — Sob demanda: só quando você pedir.
C — Híbrido: cron só detecta e lista ("você tem 2 gravações novas não processadas"), sem processar nada.
Recomendação: C. Cron que processa sozinho gera ruído e gasta tokens em gravação de 2 segundos (você tem várias). Detectar e avisar respeita a Regra dos 3x e mantém você no controle do que vale virar projeto. Não existe webhook do Plaud — só polling; list_files é 1 GET barato.
D4

A — ~/jarbas-vault/03_gravacoes/YYYY-MM/<data>-<slug>.md (acervo cronológico citável).
B — Dentro do projeto que originou (.projeto/<nome>/v1/absorcao/).
C — A + pointer no projeto: acervo é a fonte, projeto referencia via wikilink.
Recomendação: C. Uma gravação frequentemente alimenta mais de um projeto (a de 27/07 toca modelos, olivia e acervo). Duplicar conteúdo quebra DRY; o wikilink resolve — a gravação vira artefato citável.

B — Manual: eu leio a gravação e você decide o que fazer.
Recomendação: A, condicionada a D1=B (a skill é o veículo). É o maior ganho de atrito: das 15 gravações recentes, ao menos 5 viraram projeto — esse caminho seria usado toda semana.

Riscos que importam para você

os 3 que dependem de comportamento humano
R3 impacto alto prob. média

LGPD — o controle real é o que se fala

Gravação de reunião com cliente contém dados pessoais e sobe para nuvem US (S3 us-west-2), com telemetria PostHog por cima. O áudio já sobe no sync — não há como filtrar depois.

Mitigação: não falar CPF nem número de processo em voz. Conteúdo sensível → transcrição local (D2), sem gerar texto na nuvem.
R4 impacto médio prob. média

Sync pendente = falso "não achei"

Se o celular não sincronizou, a gravação simplesmente não existe para mim — e a busca volta vazia como se fosse erro de termo.

Mitigação: quando eu não encontrar uma gravação que você jura ter feito, a primeira hipótese é sync pendente, não erro de busca. Confirmar no app antes de investigar.
R9 impacto médio prob. alta em reunião

Transcrição local não tem diarização

O whisper local devolve texto corrido, tudo numa voz só. Em reunião com 2+ pessoas isso distorce quem disse o quê — e erro de atribuição de fala é erro de fato.

Mitigação: reunião com 2+ pessoas → transcrever no app (D2=C). Nunca atribuir fala em transcrição local.
