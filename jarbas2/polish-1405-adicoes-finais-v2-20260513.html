Achados-chave
  • Pipeline JÁ tem conceito peticao_simples como tipo 1ª classe
  • _loader.mjs:27 mapeia peticao_simples: MANIFESTACAO_CONFIG
  • getMaxConcurrent('peticao_simples') === 1
  • Frontend tem PeticaoSimplesView.tsx que ativa quando analisarProcesso=false && modeloSkeleton.blocos==0
Gaps reais identificados
  • montarPecaBase retorna HTML vazio quando topicos=[] → Sonnet escreve do zero (alucinação alta)
  • Caminho B template assembly só aciona com placeholder_codigo formal — os 17 modelos BV custom têm html bruto sem {{...}}
  • Selector BV cobre só empresas_categorias=[ORGAO_RESTRITIVO] — 14 Réplicas sem tags fora do escopo
Recomendação técnica

Detector isModeloAutoSuficiente com sinais:

  1. topicos === 0
  2. html_rico > 3000
  3. html_rico < 50KB (guard rail contra legacy bloated)
  4. Sem placeholders {{...}}

Seção 7 — Ideias Finais de Última Hora (Christian pediu)

💡 1. Smoke 348 vira ferramenta permanente

Após polish-1405, o smoke 348 pode virar cron noturno que testa todos os modelos semanalmente. Identifica regressões antes do usuário pegar.

Esforço: 2h (cron + Telegram report)

💡 2. Auto-tagger de modelos novos

Quando equipe sobe modelo novo via Step Editor, Sonnet sugere tags automaticamente baseado no conteúdo. Reduz 95% do trabalho manual de tagueamento.

Esforço: 4h · ROI alto se Heloísa adicionar 5+ modelos/mês

💡 3. "Modelo Score" no Step 2

Cada modelo recebe score de qualidade automático (cobertura de tags + completude HTML rico + taxa de erro histórica). UI mostra "★ 9.2" ao lado do nome. Usuária prefere modelos top-rated.

Esforço: 6h

💡 4. Persona-aware no Step 1

Hoje persona é detectada APÓS escolher modelo. Step 1 já mostra avatar persona (Christian vs Heloísa) baseado em advogado_id da sessão. Evita confusão.

Esforço: 2h

💡 5. RAG por advogado + cross-org (opt-in)

Hoje RAG limita a organizacao_id. Para advogados que TÊM peças bem-sucedidas em outros escritórios MdFlow, opt-in para usar RAG cross-org.

Esforço: 4h + LGPD review

💡 6. Modelo recommendation dashboard

Telemetria: qual modelo é trocado pelo usuário no Step 2? Dashboard semanal: top 5 modelos trocados → trigger refactor/deprecate.

Esforço: 3h + RPC + view

💡 7. "Olivia learns from corrections"

Quando usuária edita peça no Step 3 (vibelaw correção), registra diff em olivia_user_overrides e periodicamente cria mini-dataset para fine-tune ou few-shot. Já em D43 ideia 4 — formalizar.

Esforço: 4h registrar + futuro fine-tune

💡 8. Boris federado entre orgs

Boris hoje valida só org Midas. Boris federado = orgs MdFlow podem opcionalmente usar Boris (cobra ou não). Vira diferencial SaaS. Considerar v2 polish-1406.

Esforço: 8h (multi-tenant Boris) + sales
