6. 4 Decisões D-IO-01..04 — você decide

🔵 D-IO-01 — pilares (bool) → kpis em resumo_executivo?

Contexto: Schema v3 tem pilares.{prova_dano, nexo_causal, ...} (bool). Schema v4 tem resumo_executivo.kpis: Array<{label, valor, hint, trend}> (mais rico visual).

A) Migrar pilares → kpis (frontend renderiza progress bar + trend)
B) Manter ambos (legado + novo)
C) Eliminar pilares total (frontend não usa mais)
Recomendação Jarbas: A — migrar para kpis. Schema v4 é mais rico (trend up/down/flat); evita campo morto futuramente.

🔵 D-IO-02 — cruzamento_dados → provas.cruzamento_re?

Contexto: Schema v3 tem cruzamento_dados que cruza dados ré com prova. Schema v4 atual NÃO TEM. Precisa estender schema v4.

A) Estender schema v4 com provas.cruzamento_re
B) Remover cruzamento_dados (frontend não usa)
C) Manter v3 paralelo (dual-write contínuo)
Recomendação Jarbas: A — estender v4. Cruzamento de dados é argumento jurídico importante (Tema 710 STJ, BV específico). Frontend pode renderizar em seção provas.

🔵 D-IO-03 — Hierarquia respostas > considerações > modelo no prompt geracao.mjs?

Contexto: M2 introduz respostas_perguntas[]. Fidelidade alta diz "95% blocos do modelo". Sem hierarquia, LLM pode ignorar respostas em modo alta.

A) Hierarquia explícita: respostas_usuario (100) > consideracoes_topico (80) > modelo_canonico (60)
B) Sem hierarquia (LLM decide)
C) Hierarquia inversa (modelo sempre vence)
Recomendação Jarbas: A — hierarquia explícita. Usuário escreveu resposta = sabe o que faz. Modelo é fallback estrutural. Sem hierarquia, respostas viram lixo.

🔵 D-IO-04 — Frontend enviar ordem_override_usuario: true quando drag-droppou?

Contexto: Frontend permite drag-drop tópicos. Backend ORDEM_CANONICA_POR_CATEGORIA pode reordenar de volta.

A) Frontend envia flag ordem_override_usuario: true — backend respeita
B) Backend nunca reordena (canônica vira sugestão, não enforce)
C) Drag-drop apenas visual (backend mantém canônica)
Recomendação Jarbas: A — flag explícita. Respeitar drag-drop do usuário sem perder canônica como default. Backward compat (flag default false).
