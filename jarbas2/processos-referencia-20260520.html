🚨
Campos canônicos — NUNCA usar _new direto no frontend:
restricao_valor e restricao_data: a RPC rpc_processo_get_completo já resolve via COALESCE(restricao_valor_new, restricao_valor). O frontend NUNCA deve ler ou escrever _new diretamente.

status_id: FK para processos_status é o campo canônico. O campo status (TEXT legado) NÃO deve ser editado diretamente.
📌
Não existe formulário de criação manual de processos em /processos. Processos entram APENAS por:
1. Via CRM → Distribuição (RPC distribuir_lead_completo) — fluxo principal do lead-to-cash
2. Via importação CSV/XLSX (ModalImportarProcessos) — migração em massa

Envelope Canônico — Todos os Webhooks

Seção 13 — Gaps e Pendências Conhecidas

§13
📋
Itens documentados como problemas conhecidos. Não são bugs críticos bloqueantes — são inconsistências, limitações de design ou débitos técnicos que devem ser considerados ao evoluir a página.
G-01
Sem criação manual de processo
Processos só entram via CRM → Distribuição (RPC distribuir_lead_completo) ou importação CSV/XLSX. Não há formulário "Novo Processo" em /processos — isso é intencional pelo modelo lead-to-cash, mas pode confundir novos desenvolvedores.
G-02
@ts-nocheck em index.tsx e ProcessoTabDocumentos
Indica schema drift — tipos TypeScript não correspondem 100% ao banco real. Risco de regressões silenciosas ao modificar tipos sem atualizar o banco (ou vice-versa). Necessário auditoria de tipos antes de qualquer refactor maior.
G-03
Campos legados status (TEXT) vs status_id (FK)
O campo status (TEXT) coexiste com status_id (FK). Frontend canônico usa status_id, mas campo legado ainda presente e sincronizado no banco. Pode causar confusão em queries diretas ou integrações externas.
G-04
restricao_valor_new / restricao_data_new — campos intermediários de migração
Campos _new existem no banco como artefato de migração. A RPC resolve com COALESCE, mas a presença desses campos pode confundir. O frontend NUNCA deve ler ou escrever _new diretamente — sempre usar o campo sem sufixo.
G-05
Valor_causa: unidade incerta entre tabela e RPC
valor_causa é BIGINT centavos na tabela processos, mas rpc_processo_get_completo pode retornar em reais dependendo da versão da RPC. Verificar unidade retornada antes de formatar com formatBRL.
G-06
ia_status='pendente' invisível para o usuário
IaStatusBadge não exibe nada quando ia_status='pendente' — o estado inicial é completamente invisível. Pode causar confusão: o usuário não sabe se a análise IA foi solicitada ou se ainda não foi iniciada.
G-07
Seleção máximo 50 — não escala para bulk operations grandes
Limite hard-coded de 50 processos por seleção. Para organizações com centenas de processos para arquivar, isso força múltiplas operações. Candidato a feature de "selecionar todos os N resultados do filtro".
G-08
ProcessoView tab controlada vs URL — comportamento diferente por contexto
No drawer de /processos, a tab não sincroniza com a URL (controlada pelo pai). Ao navegar para /pagina_processo, a tab reseta para 'dados'. Usuário que estava na aba "decisoes" no drawer e abre a página completa perde o contexto de qual aba estava.
G-09
Export polling sem Supabase Realtime
Polling a cada 2s é menos eficiente do que Supabase Realtime (channel postgres_changes). Para exportações grandes, o usuário aguarda polling com delay máximo de 2s por update. Candidato a migração para Realtime quando a feature estabilizar.
G-10
Importação sem preview client-side de XLSX
Preview (5 primeiras linhas + validação CNJ) só está disponível para CSV. Arquivos XLSX são enviados para o servidor sem nenhuma validação ou preview client-side — o usuário não tem feedback antes do processamento.
