4Minhas considerações sobre o projeto

O que joga a favor

  • Risco de domínio ≈ zero: a lógica difícil (placeholders reais, substituição, montagem HTML, masks) é portada 1:1 com as 5 suítes de teste — o que muda é casca, não cérebro.
  • Contrato de backend congelado: o payload do webhook e o pipeline n8n→GAS não mudam. O risco clássico de "frontend novo quebra integração" não existe aqui.
  • Isolamento VibeLaw por construção: slot pattern é opt-in; quem não registra slot renderiza byte-igual. O smoke T03 é gate antes de qualquer wave pesada.
  • Todos os contratos de dados verificados em produção (prosrc das RPCs, colunas, NOT NULL de olivia_indicacoes_acordo) — nada foi assumido.
  • Mockups fecham ambiguidade: M1-M6 aprovados eliminam o vai-e-vem de interpretação visual que costuma custar 30% do tempo.

Onde mora o risco (e a mitigação)

  • Migration da store v3→v4: abas persistidas de usuários reais. Mitigação: migration ADITIVA pura + teste com payload v3 real copiado do browser.
  • Delete de 13.281 LOC na W5: lição vibelaw0806 aplicada — varrer entry points com grep ANTES + validar com npm run build (rollup), porque tsc não pega import relativo morto.
  • Bug do retry (v1) renascer: o GenerationOverlay antigo permitia POST duplicado. No novo, retry só renderiza com status==='erro' — é AC explícito do T10 e item do DoD.
  • Scroll esquecido (reincidência conhecida): virou requisito de aceitação por painel + auditoria 1366×768 no DoD — não depende de memória, depende de gate.
  • Smoke visual precisa de browser: T03 e a fidelidade M1-M6 têm verificação visual. Se o executor não tiver browser, esses itens viram checklist para você validar — o resto do DoD é automatizável.

Opinião honesta

Este é o projeto certo na hora certa: o vibelaw1006 acabou de provar que o padrão "shell imersivo + pacote novo + delete do antigo" funciona (foi exatamente o W8 de lá), e o Smart Blocks é a última peça da /olivia presa em estrutura legada (olivia-antiga/ com nome mentiroso). O wizard como default (sua inversão da minha recomendação) é defensável: o público-alvo do SB é operação repetitiva, e Typeform com teclado é mais rápido que split para quem já conhece as teses — o split fica a 1 clique para power users. A única coisa que eu pediria de volta: depois do T03 (gate VibeLaw), dê uma olhada de 2 minutos no header antes de eu seguir para W2 — é o único ponto onde um falso-positivo meu custaria caro.
