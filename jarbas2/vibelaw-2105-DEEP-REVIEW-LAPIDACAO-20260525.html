05O que NÃO funciona (gaps reais)

Gap #1 — IA tem liberdade demais para parafrasear

Sintoma: Peças têm estrutura próxima do modelo mas texto reescrito. Equipe relata "criou redação livre" e "deve usar pré-textos validados verbatim".

Causa raiz: System prompt diz "blocos primeiro" mas T-02 retorna lista de blocos e a IA decide usar/adaptar/ignorar. Sem etapa que MONTE o template + blocos cru ANTES de a IA olhar.

Solução: Inverter o pipeline. T-01 + T-02 + T-04 + T-13 + T-15 DEVEM rodar 100% determinístico e PRODUZIR um draft já com blocos verbatim e juris inseridas. SÓ DEPOIS Opus 4.7 é chamado pra refinar com instruções claras de "não alterar estrutura, só ajustar transições".

Gap #2 — Jurisprudência por tema, não por tag/modelo

Sintoma: T-03 retorna juris que matcham keywords no tema, não as curadas no modelo. Equipe: "as jurisprudências corretas seriam aquelas vinculadas ao modelo".

Causa raiz: T-03 atual: search_juris_rag(tema, advogado_id, persona_estado). Backend chama fn_olivia_juris_para_geracao (curadoria do advogado) ou ILIKE. Mas não filtra por modelo_grupo_id via olivia_modelo_juris.

Solução: Estender T-03 com modelo_grupo_id opcional. Quando passado, faz JOIN olivia_modelo_juris ON juris_id. Juris curadas pro modelo SEMPRE prioritárias. Fallback ILIKE só quando modelo não tem N juris suficientes.

Gap #3 — Documentos do processo não são lidos pela IA

Sintoma: Peças genéricas, sem citar evento/ID/página de contestação. Equipe: 21 itens (99-119) pedem "menção direta a documentos".

Causa raiz: Step 1 tem upload de PDFs ✓. vibe.mjs injeta metadata no user_msg ✓. Mas T-19 read_pdf_documentos foi criada como stub e nunca foi chamada de verdade pela IA. A IA só vê nome+tamanho dos arquivos.

Solução: Implementar T-19 real (Anthropic Files API beta — upload PDF + recebe file_id) + Adicionar instrução no system prompt: "Se houver documentos anexados, chame T-19 ANTES de qualquer outra tool. Use file_ids para citar trechos específicos na fundamentação."

Gap #4 — Endereçamento, título e fecho não vêm do modelo

Sintoma: "EXMO. SR. DR." abreviado vs "Excelentíssimo Senhor Doutor" extenso. "RÉPLICA À CONTESTAÇÃO" h1 desproporcional. Cidade/OAB inventadas pela IA.

Causa raiz: conteudo_template_html_rico tem o endereçamento + título + fecho corretos, mas a IA reescreve baseada no system prompt em vez de copiar do modelo.

Solução: T-01 deve retornar o template com regiões marcadas {{ENDERECAMENTO}}, {{TITULO}}, {{FECHO}}, {{ASSINATURA}}. T-04 substitui essas regiões com dados de advogados.cabecalho_escritorio + rodape_peticao + cidade_assinatura. IA proibida de escrever esses 4 trechos.

Gap #5 — Sem score real de similaridade com modelo / peça-referência

Sintoma: T-10 retorna "modelo_similarity: 8.5" mas valor não é medido — é heurística vaga. Não há comparação direta com peça-referência do mesmo advogado/tipo.

Solução: T-10 calcula cosine real entre peticao_html gerada e: (a) modelo.conteudo_template_html_rico · (b) olivia_historico peças aprovadas (status=CONCLUIDO, score_revisor>=8.5) do mesmo modelo_grupo_id. Score por área "modelo_similarity" reflete cosine real.

Gap #6 — Sem feedback loop de aprovação humana

Sintoma: Operador aprova/edita peça mas correções não voltam pro sistema. Mesmos erros repetem.

Solução: Step 3 já tem FeedbackAdvogado. Conectar com olivia_blocos_texto — quando user edita um bloco no editor, oferecer "Promover essa edição como novo bloco padrão" (criando bloco_grupo_id novo + version). Ciclo de aprendizado.

O que mudaria se repensássemos arquitetura?

Opção A — Manter (recomendado)
  • Continua single-agent Opus 4.7
  • Inverte ordem: tools determinísticas montam draft cru, IA só refina
  • 3-4 semanas de Sprint 3 → score 9.0+
  • Risco: baixo (incrementa o que já funciona)
  • Trade-off: ✓ velocidade + ✓ aproveita o que tá pronto
Opção B — Multi-agent especializado
  • 1 agente por categoria (preliminares/mérito/dano/pedidos)
  • Era o design V1 → fracassou (273 reclamações Leonardo)
  • State management fica caótico
  • Custo 4× mais alto (4 inferências paralelas)
  • Trade-off: ✗ regressão pro design que NÃO funcionou
Opção C — RAG-only sem IA generativa
  • Pipeline 100% determinístico (template + blocos + juris via SQL)
  • Score limitado a ~7.5 (sem refinamento contextual)
  • Não consegue mencionar documentos do processo
  • Não consegue conectar argumentos entre seções
  • Trade-off: ✗ teto de qualidade muito baixo
Opção D — Híbrido Smart Blocks + IA refina
  • User seleciona blocos manualmente (como SB v2)
  • IA Opus 4.7 só refina transições + adapta dados
  • Score esperado 8.5+ mas perde "automação"
  • Para o usuário fluxo se torna SB v2 + refinamento
  • Trade-off: ⚠ vira features cruzadas — mas é uma terceira opção útil
Recomendação CC: Opção A (manter + lapidar) + considerar adicionar Opção D como modo opcional ("Vibe + revisão manual") no Step 2 quando user quer controle granular.
