Documentacao tecnica completa dos 3 workflows responsaveis pela geracao automatizada de peticoes iniciais no MdFlow. Atualizado 2026-05-26.

Visao Geral

Tres workflows estao ativos no n8n para geracao de peticoes iniciais. Todos retornam HTTP 202 imediato (fire-and-forget) — o pipeline roda assincronamente apos a resposta.

HTTP  Node 2 — Buscar Processo

4 queries paralelas ao Supabase REST API, depois 5 queries adicionais para montar o contexto completo.

Fase 1 — 4 Queries Paralelas

  • 1
    olivia_modelos_grupo — filtrado por modelo_grupo_id. Retorna nome do modelo e configuracoes.
  • 2
    advogados — filtrado por advogado_id. Retorna nome, OAB, UF.
  • 3
    processos — campos: id, numero_cnj, tipo_processo, objeto, observacoes, valor_causa, empresa_nome, cliente_nome, vara, comarca, ajg_concedida, restricao_orgao_nome, restricao_valor, restricao_data_new, restricao_tipo, ia_resumo, detalhes, cliente_id, empresa_id, advogado_id, restricao_id
  • 4
    olivia_playbooks — filtrado por playbook_id. Retorna instrucoes customizadas.

Fase 2 — Queries Adicionais

  • 5
    clientes — dados completos do cliente (nome, CPF, RG, endereco, cidade, UF)
  • 6
    empresas — dados da empresa re (razao_social, CNPJ)
  • 7
    olivia_modelos_peticao — versao ativa do modelo (status = 'ativo'), incluindo prompt_sistema, instrucoes_ia, prompt_instrucoes
  • 8
    restricoes — para obter drive_pasta_id
  • 9
    _contexto_fatos — montado a partir de ia_resumo.resumo, pontos_fortes, lacunas, tipo_negativacao, prescrita
Fallback quando sem analise IA: [AVISO: processo sem analise IA — usando dados basicos]

HTTP  Node 3 — OlivIA Peticao (Claude)

Chama a Anthropic API diretamente. Constroi o prompt a partir de todos os dados coletados no Node 2.

Modelo — qualidade padrao
claude-sonnet-4-6 — max_tokens: 6000, temperature: 0.3
Modelo — pensamento estendido
claude-opus-4-5 — max_tokens: 8000
Timeout
180 segundos
System Prompt (prioridade)
versao.prompt_sistema > versao.instrucoes_ia > fallback hardcoded

User Prompt — Dados Injetados

  • 1
    Numero CNJ, tipo de acao, objeto, valor da causa, vara, comarca, AJG concedida
  • 2
    Orgao de restricao, valor, data da restricao (negativacao indevida)
  • 3
    Contexto dos fatos (ia_resumo)
  • 4
    Partes: autor (nome, CPF, RG, endereco), reu (razao_social, CNPJ — sem endereco), advogado (nome, OAB/UF)
  • 5
    Respostas da triagem, analise de provas, documentos juntados
  • 6
    Contestacao (se presente), playbook, instrucoes do advogado
  • 7
    Instrucoes do modelo (versao.prompt_instrucoes)
Formato obrigatorio retornado: HTML completo com <h2> para secoes e <p> para paragrafos.

Workflow 3 — Dry Run (Validacao Visual)

Gera um Google Doc com prefixo [DRY-RUN] para validar o template visualmente. Nao persiste nada no banco.

N8N-PETICAO-INICIAL-DRY-RUN v1 ATIVO ID: 67F72Huv2yKzrZGb 2026-05-05
Rota
POST /webhook/peticao-inicial/dry-run
Autenticacao
Sem header de auth
Persistencia
Nao persiste no banco
Proposito
Validacao visual do template antes de producao

Input

JSON
{ "processo_id": "uuid", "organizacao_id": "uuid" }

Pipeline

  • 1
    Chama RPC rpc_solicitar_peticao_inicial(p_processo_id) — retorna { modelo (Drive file ID), pasta_drive_id, arquivo_nome_base, campos_substituicao, blocos }
  • 2
    Obtem access token Google via OAuth2 refresh (client_id + refresh_token configurados no n8n)
  • 3
    Copia template no Google Drive: POST /files/{templateId}/copy com prefixo [DRY-RUN] no nome
  • 4
    Substitui {{campos}} via Docs API batchUpdate/replaceAllText
NAO exporta PDF, NAO faz upload no Storage, NAO persiste no banco. Apague manualmente o arquivo do Drive apos revisar.
